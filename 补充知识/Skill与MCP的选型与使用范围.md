# Skill 与 MCP 的选型与使用范围

> 本文回答三个问题：Skill 和 MCP 的本质区别是什么？什么情况下开发 MCP？什么情况下开发 Skill？

---

## 1. 一句话核心区分

> **Skill 教会 Agent「怎么做」；MCP 给 Agent「新的工具」。**

- **Skill**：知识/流程的注入（说明书）。
- **MCP**：能力的扩展（新器官）。

前者是提示词工程的组织方式，后者是工具连接协议。

---

## 2. 本质区别对比

| 维度 | Skill | MCP |
| --- | --- | --- |
| **本质** | 一段「指令 + 方法论 + 可选脚本」的提示词包 | 一个运行中的服务进程，通过协议暴露工具 |
| **扩展的是** | Agent 的**知识、流程、领域规范** | Agent 的**可执行能力、外部连接** |
| **运行时** | 静态文本，被加载进上下文 | 独立进程，通过 client-server 协议动态调用 |
| **状态** | 无状态 | 可有状态、有连接、有持久化 |
| **给 Agent 什么** | 「遇到这类任务该按什么 SOP 做」 | 「现在你可以调用这个函数/读这个数据」 |
| **成本** | 极低，写 Markdown 即可 | 高，需开发 + 部署 + 维护服务 |
| **交付物** | `SKILL.md`（+ 辅助脚本） | MCP Server（代码 + 工具 schema） |

一句话记忆：**Skill 是「说明书」，MCP 是「新器官」。**

---

## 3. 什么情况开发 Skill

当任务**不需要新的底层能力**，Agent 用现有工具（写代码、跑命令、读文件、已有 MCP）就能完成，缺的只是「更专业的指导」：

- 沉淀**领域方法论 / SOP**：科研绘图规范、论文投稿流程、专利交底书生成步骤
- 封装**可复用的提示词模板**、检查清单、风格约定
- 教会 Agent **如何组合现有工具**完成复杂任务（先做什么、再做什么、注意什么坑）
- 领域知识更新快、需要频繁迭代说明文字的场景

**特征**：Agent 本来就能做，只是希望它做得更专业、更一致、更少犯错。

---

## 4. 什么情况开发 MCP

当 Agent **缺少某种真正的外部能力**，靠「自己写代码」够不到，必须连接外部系统时：

- 访问**外部实时数据 / API**：数据库、SaaS 平台、内部系统
- 控制**本地进程 / 软件**：浏览器（CDP）、Office/设计软件（COM）、GUI 应用（UI Automation）
- 需要**持久状态 / 连接**：长连接、会话缓存、鉴权会话
- 需要**权限隔离、异步后台任务、多客户端复用同一服务**
- 需要在**多个 Agent / 客户端之间共享**同一套工具

**特征**：Agent 没有这个工具就「物理上做不到」，不是指导能解决的。

---

## 5. 决策树

```
任务缺的是什么？
│
├─ 缺「指导/规范/流程」──▶ 用现有工具就能做，只是不够专业 ──▶ 开发 Skill
│
└─ 缺「执行能力/外部连接」──▶ 继续判断
        │
        ├─ 必须连接外部系统/数据/进程（Agent 沙箱外）──▶ 开发 MCP
        │
        └─ Agent 自己写脚本/跑命令就能完成 ──▶ 开发 Skill（把脚本附在 SKILL.md 里）
```

---

## 6. 实际案例对照：WPS / Excel 自动化工具

以「驱动 WPS/Excel 生成文档」这类工具为例，其底层是 Python 脚本（通过 COM 调用软件），**做成哪种形态取决于包装方式**：

| 形态 | 做法 | 结果 |
| --- | --- | --- |
| **Skill 形态** | `SKILL.md` 写明「用 `python cli.py ...` 生成 PPT」，Agent 自己去执行脚本 | Agent 通过「读说明 + 跑命令」完成任务 |
| **MCP 形态** | 把脚本包装成 MCP Server，暴露 `create_ppt` / `export_pdf` 等工具 | Agent 直接「调用工具函数」完成任务 |

**判断依据**：

- 如果 Agent 能在自己的沙箱里直接跑 Python 脚本 → **Skill 就够了**，无需 MCP。
- 如果 COM 调用必须发生在**特定机器、特定进程、需要保持窗口/会话状态**，而 Agent 运行环境无法直接触达 → **需要 MCP**，让 Server 常驻在那台机器上暴露工具。

---

## 7. 两者不是互斥的，而是组合

最佳实践往往是一起用：

```
MCP Server  ──暴露──▶ 工具（write_cell / add_chart / export_pdf）
                          ▲
                          │ 调用
Skill（SKILL.md）─────▶ 教 Agent「做销售报表该用什么 SOP、先写表头再填数据最后质检」
```

- **MCP 提供「器官」**：让 Agent 能真正驱动软件 / 连接数据。
- **Skill 提供「手法」**：教 Agent 用这些器官时遵循专业流程、避坑。

分工清晰：**MCP 管「能不能做」，Skill 管「做得好不好」。**

---

## 8. 总结

1. 缺**知识/流程** → **Skill**（写 Markdown，零成本）。
2. 缺**能力/连接** → **MCP**（写 Server，需部署）。
3. 底层代码能直接跑 → 优先 **Skill**；必须常驻服务/远程触达 → 才上 **MCP**。
