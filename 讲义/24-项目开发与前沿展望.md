## 三、综合项目开发实践（90 分钟）

### 3.1 本节课目标

本节课是你们作为 AI 应用开发者的第一次完整实践。不在于做出多么完美的产品，而在于**从 0 到 1 走完一个完整流程**。

### 3.2 项目方向建议

以下每个方向都给出了"最小可行版本（MVP）"的范围——足够你在 90 分钟内完成核心功能：

| 方向 | MVP 目标 | 技术要点 | 难度 |
|------|---------|----------|------|
| **知识库问答** | 上传 1 个 PDF，基于内容回答 3 个问题 | RAG + Embedding + ChromaDB | ★★★ |
| **AI 聊天助手** | 带 System Prompt + 多轮对话的 Web 聊天应用 | Streamlit + API + Multi-turn | ★★☆ |
| **AI 文案工具** | 选择平台（小红书/公众号/抖音），输入主题 → 生成文案 | Prompt Engineering + Structured Output | ★★☆ |
| **AI 数据分析** | 上传 CSV → AI 解读趋势并生成图表 | Pandas + Tool Calling + 可视化 | ★★★ |
| **AI 学习助手** | 输入知识点 → AI 生成练习题 + 批改 | Prompt Engineering + API | ★★☆ |
| **Agent 工具调用** | AI 能调用至少 2 个工具（天气/计算/搜索/文件） | Function Calling + LangChain | ★★★ |

### 3.3 开发要求

- **MVP 优先**：先做核心功能，能跑通再说。不要一开始就追求完美 UI。
- **AI 辅助编程**：大胆使用 ChatGPT / Claude / Cursor 来帮你写代码和 Debug。这是本课程一直强调的核心能力。
- **代码管理**：建一个 GitHub 仓库（或本地文件夹），包含 README.md 说明如何运行。
- **API 安全**：不要把 API Key 写在代码里，使用 `.env` 文件或环境变量。

### 3.4 课堂开发流程

```
00:00 - 00:10  确定选题，明确 MVP 范围（写在纸上或笔记里）
00:10 - 00:15  搭建项目骨架（文件结构、依赖安装）
00:15 - 00:45  实现核心逻辑（API 调用 / RAG / Agent Loop）
00:45 - 01:00  添加 UI 界面（Streamlit / Gradio 最快）
01:00 - 01:15  测试与 Debug（跑 3 个测试用例，修 Bug）
01:15 - 01:30  完善文档（README）+ 互相体验同学的项目
```

### 3.5 遇到问题怎么办？

1. **复制错误信息 → 问 AI**：把完整的报错信息复制给 ChatGPT/Claude，90% 的问题都能解决。
2. **降低复杂度**：如果卡住了，先简化——暂时去掉 UI，只跑通核心代码。
3. **5 分钟原则**：如果一个 Bug 5 分钟没有头绪，立刻问 AI 或请教同学。
4. **接受不完美**：第一版代码长得丑、跑得慢、功能少，都是正常的。先有再说。

### 5.2 核心前沿技术详解

#### 5.2.1 MoE（混合专家模型，Mixture of Experts）

**是什么？**

MoE 是一种模型架构创新。传统的大模型（Dense Model）在处理每个 Token 时会激活**所有参数**。而 MoE 模型将模型分成多个"专家"子网络，处理每个 Token 时只激活其中**一小部分专家**。

```
传统 Dense 模型：                    MoE 模型：
每个 Token 激活全部参数              每个 Token 只激活部分专家
┌──────────────────┐               ┌──────────────────┐
│  ████████████████ │               │  ▓▓▓▓░░░░░░░░░░░░ │
│  ████████████████ │               │  ░░░░▓▓▓▓▓▓░░░░░░ │
│  ████████████████ │               │  ░░░░░░░░▓▓▓▓▓▓▓▓ │
│  激活 100% 参数    │               │  激活 ~20% 参数     │
└──────────────────┘               └──────────────────┘ 
```

**为什么重要？**

- **效率革命**：用更少的计算量获得更强的能力。DeepSeek-V3 有 671B 总参数，但每个 Token 只激活约 37B 参数，推理成本大幅降低。
- **规模化关键**：MoE 让"万亿参数"模型成为可能——否则全参数激活的计算成本根本无法承受。
- **代表模型**：Mixtral 8×7B（Mistral）、DeepSeek-V2/V3、GPT-4（据传使用 MoE）、Qwen-MoE。

**技术原理简述**：

1. 模型包含 N 个"专家"（每个专家是一个独立的前馈网络）。
2. 一个"路由网络"（Router/Gate）负责判断每个 Token 应该发送给哪 2-3 个专家处理。
3. 路由网络和专家一起训练，自动学会分工——有的专家擅长代码、有的擅长数学、有的擅长文学。
4. 最终输出是多个专家输出的加权和。

> **类比**：传统模型像一个"全科医生"，每个病人都要经过他的完整诊疗。MoE 像一个"医院"——有心脏科、骨科、皮肤科等多位专家，病人根据症状被分诊到对应的 2-3 个科室，效率更高、专业性更强。

#### 5.2.2 推理模型（Reasoning Models / o-series / R1-style）

**是什么？**

推理模型是一类经过特殊训练、能够进行**深度思考**的模型。它们在回答问题之前会先进行长时间的"内心独白"（Chain of Thought），探索多种思路、自我纠错，然后再给出最终答案。

**发展脉络**：

```
2024.09  OpenAI o1-preview 发布
         ├── 首次展示"推理时计算"(Inference-time Compute)
         └── 在数学竞赛(AIME)、编程竞赛(Codeforces)上大幅领先 GPT-4o

2024.12  OpenAI o1 正式版 + o1-pro
         ├── 更强的推理深度
         └── 在科学推理、复杂数学上追平人类专家

2025.01  DeepSeek-R1 发布（开源！）
         ├── 首次开源达到 o1 级别的推理能力
         ├── 论文公开了训练方法：纯强化学习即可激发推理能力
         └── 引发全球关注——"中国团队用更少资源达到顶级水平"

2025.03  OpenAI o3 / o4-mini
         ├── 推理能力进一步提升
         └── 引入"推理努力程度"可调（low/medium/high）

2025-    各厂商跟进推理模型路线
2026     ├── Claude 加入 extended thinking 模式
         ├── Gemini 推出 thinking mode
         └── 推理模型成为大模型标配能力
```

**技术原理**：

推理模型的核心是**强化学习**（Reinforcement Learning）——让模型在训练中学会"多思考几步会得到更好的答案"。

- **RLHF → RL for Reasoning**：传统 RLHF 让模型学"什么是好回答"，推理 RL 让模型学"什么是好的思考过程"。
- **奖励信号**：不需要人类标注每一步思考的好坏——数学题的答案对不对、代码能不能跑通，这些是天然的自动化奖励信号。
- **涌现的推理行为**：DeepSeek-R1 论文中有一个令人震惊的发现——即使不提供"思考链"示例，纯强化学习也能让模型自己学会"等等，我再想想""让我换个角度"等反思行为。这是推理能力的涌现。

**对开发者的影响**：

- 对于需要深度推理的任务（数学、编程、逻辑分析），优先选择推理模型。
- 推理模型通常**更慢、更贵**，但对复杂问题的效果显著更好。
- 在 Agent 架构中，可以用推理模型做"规划与决策"，用常规模型做"执行与交互"。

#### 5.2.3 多模态大模型（Multimodal LLMs）

**是什么？**

多模态模型能够同时理解和生成**多种类型的数据**——文本、图像、音频、视频、代码。

```
传统 LLM：                        多模态 LLM：
  文本输入 → 文本输出                文本/图像/音频/视频输入 → 文本/图像/音频输出
  
  只能"读文字、写文字"              能"看图说话、听声辨意、文生图、图生文"
```

**发展脉络**：

```
2023.03  GPT-4V(ision) — 首个顶级多模态语言模型
2023.09  GPT-4V 开放 — 图像理解能力惊艳世界
2023.12  Gemini 1.0 — Google 首款原生多模态模型（训练时就包含多模态数据）
2024.05  GPT-4o ("o" for "omni") — 实时语音+视觉+文本，平均 320ms 响应
2024.10  Claude 3.5 支持图像理解（PDF/图表/照片）
2025.01  Gemini 2.0 — 原生多模态 + Agent 能力
2025.05  GPT-5 — 统一多模态，图像生成内置（不再需要单独的 DALL-E）
2025-    视频理解、实时视频对话逐步成熟
2026
```

**技术原理简述**：

多模态的核心挑战是**对齐**（Alignment）——如何让"猫的图片"和"猫这个文字"在模型的表示空间中指向同一个概念？

- **视觉编码器**（Vision Encoder）：将图像切割成小块（Patches），类似 Token 化文本的方式，将图像转为向量序列。
- **跨模态注意力**：让文本 Token 和图像 Patch 在 Transformer 的注意力机制中互相"看到"对方。
- **原生多模态 vs 外挂多模态**：Gemini 和 GPT-4o 是"原生"多模态——从预训练阶段就用混合数据训练；而早期方案是"外挂"——先训练好文本模型，再加一个视觉编码器。原生方案的融合更深、能力更强。
- **音频多模态**：语音不再需要"ASR 转文字 → LLM 处理 → TTS 转语音"的流水线。GPT-4o 直接理解音频中的语气、情绪、停顿，能感知"你是在开玩笑还是在生气"。

#### 5.2.4 长上下文（Long Context / Infinite Context）

**是什么？**

指模型一次能处理的文本长度。从 2023 年的 4K-8K Token，到 2026 年的 1M+ Token（相当于一次读完《三体》三部曲），长上下文能力在过去两年中经历了爆发式增长。

**发展脉络**：

```
2023.03  GPT-4          8K / 32K Token
2023.10  Claude 2       100K Token（约 7.5 万英文单词）
2024.02  Gemini 1.5     1M Token（首次突破百万，约 75 万词）
2024.04  GPT-4 Turbo    128K Token
2024.06  Claude 3.5     200K Token
2024.10  Gemini 1.5 Pro 2M Token（约 150 万词，读完一本《战争与和平》还剩空间）
2025.05  Gemini 2.5 Pro 2M Token（保持记录）
2025.06  Claude 5       200K Token（长文本质量 > 长文本容量）
2026     各厂商          200K-2M 成为主流配置
```

**技术原理**：

长上下文的主要技术突破来自两个方面：

- **位置编码改进**：Transformer 需要知道每个 Token 的位置。原始的绝对位置编码在训练长度之外完全失效。RoPE（旋转位置编码，Rotary Position Embedding）通过高维旋转来表示相对位置，天然支持外推到更长的序列。
- **注意力机制优化**：标准的 Self-Attention 复杂度是 O(n²)（n 是 Token 数）。100 万 Token 意味着 1 万亿次注意力计算——这不可能。解决方案包括：
  - **Ring Attention**：将序列分布在多个 GPU 上，每个 GPU 只计算自己的片段，通过环形通信共享注意力信息。
  - **FlashAttention**：通过分块计算和 IO 优化，将注意力计算的显存占用从 O(n²) 降到 O(n)。
  - **稀疏注意力**：不是每个 Token 都关注所有 Token，只关注最相关的一部分。

> **关键洞察**："能做长上下文"和"长上下文用得好"是两回事。学术界有一个著名的"大海捞针"（Needle in a Haystack）测试——在 100K Token 的长文本中藏一句话，看模型能否找到。目前各模型在这方面差异很大。Claude 和 Gemini 在长文本的**精确检索**上表现最好。

#### 5.2.5 Agent 工程化与协议标准化

**Agent ≠ 框架**。2025-2026 年，Agent 领域最大的变化是从"手写 Agent Loop"走向"工程化 Agent 基础设施"。

**三大协议**：

| 协议 | 全称 | 解决什么问题 | 当前状态（2026） |
|------|------|-------------|-----------------|
| **MCP** | Model Context Protocol | Agent **如何连接**外部工具和数据源 | 生态爆发，1000+ 社区 Server，已被 Claude、Cursor、Zed 等广泛支持 |
| **A2A** | Agent-to-Agent | Agent **之间如何**发现、通信与协作 | Google 推动，正在成为多 Agent 系统的标准 |
| **ACP** | Agent Client Protocol | 编辑器/IDE/宿主应用 **如何与** Agent 通信 | 新兴标准，解决工具集成问题 |

**协议类比**：

```
MCP  = USB  协议（设备怎么连接电脑）
A2A  = WiFi 协议（设备之间怎么通信）
ACP  = HDMI 协议（显示器怎么接收信号）
```

**Agent 工程化的关键趋势**：

- **Agent Harness（Agent 运行框架）**：不只是"写一个 Agent"，而是为 Agent 提供完整的运行时环境——工具注册、权限管理、状态持久化、日志追踪、错误恢复。2025 年论文"AI Harness Engineering"首次将其定义为一门独立工程学科。
- **Context Engineering（上下文工程）**：从"写好 Prompt"升级为"设计 Agent 的完整信息环境"——如何组织 System Prompt、对话历史、工具定义、检索结果、记忆提取，让模型在每一步都拥有做出正确判断所需的全部信息。上下文压缩（Compaction）、上下文选择（Selection）、上下文结构化（Structuring）是三大核心技术。
- **从 Prompt → Context → Harness 的三级跳**：2023 年拼 Prompt，2024 年拼 Context，2025-2026 年拼 Harness。三者是从"会说话"到"能做事"再到"可靠地做事"的工程递进。
- **评估体系（Evals）**：没有评估就没有工程。2025-2026 年，Agent 评估从"人工看效果"走向自动化——SWE-bench（代码修复任务）、GAIA（通用助手任务）、τ-bench（工具使用任务）等基准推动了 Agent 能力的可量化进步。
- **从 Demo 到生产**：2024 年的 Agent 大多是"看起来很美"的 Demo。2025-2026 年，真正的挑战在于——如何让 Agent 在 1000 次调用中稳定运行？如何处理异常？如何控制成本？这是 Agent 工程化的核心。

#### 5.2.6 开源模型的崛起

**关键事件**：

```
2023.02  Llama 2 开源 — Meta 开启开源大模型时代
2024.04  Llama 3 发布 — 8B 和 70B，接近 GPT-4 水平
2024.12  DeepSeek-V3 发布 — 671B MoE，训练成本仅 $5.6M（GPT-4 的 ~1/20）
2025.01  DeepSeek-R1 开源 — 首个开源 o1 级别推理模型，引发全球震动

```

**开源模型的意义**：

- **降低门槛**：不依赖 API 也能在本地运行强大的模型，保护数据隐私。
- **促进创新**：DeepSeek-R1 证明了"用更少资源就能达到顶级水平"，这对整个行业是巨大的激励。
- **自定义与微调**：开源模型可以进行 LoRA 微调，适配特定领域需求——闭源模型做不到这一点。
- **成本优势**：对于大规模应用，自部署开源模型的长期成本远低于 API 调用。

#### 5.2.7 Coding Agent 的爆发

**是什么？**

Coding Agent 是专门用于**软件工程**的 AI Agent——它们能读代码、写代码、修改文件、运行测试、提交 Git、管理依赖。

**代表产品**：

| 产品 | 发布时间 | 核心特点 |
|------|---------|----------|
| **Claude Code** | 2025.02 | Anthropic 官方 CLI Agent，shell/文件/编辑/测试/权限/Hooks/Subagents/MCP |
| **Codex (OpenAI)** | 2025.05 | OpenAI 编程 Agent 平台，App/CLI/Web/IDE 多入口协作 |
| **Cursor** | 2023+ | AI-first IDE，融合 Agent 能力到编辑器 |
| **Aider** | 2023+ | 最早的终端 AI pair programming 工具 |
| **Devin** | 2024.03 | 第一个"全自主"编程 Agent（引发"程序员会被取代吗"的讨论） |
| **OpenHands** | 2024+ | 开源 coding agent，沙箱化执行 |

**Coding Agent 对 AI 学习的意义**：

Coding Agent 本身也是最好的 **Agent 工程学习样本**——它们包含了 Agent Loop、工具系统、权限控制、上下文压缩、子代理协作等所有 Agent 核心技术。学习 AI 开发的过程中，主动分析和理解你使用的 Coding Agent，就是最好的学习方式。

#### 5.2.8 模型小型化与端侧部署

**趋势**：大模型不只在云端运行——2025-2026 年，1B-8B 参数的小模型在手机、笔记本上就能跑出令人惊叹的效果。

**代表**：
- **Phi 系列**（Microsoft）：Phi-4 14B 参数，在数学推理上接近 GPT-4o 水平。
- **Gemma 系列**（Google）：开源小模型，适合端侧部署。
- **Llama 系列小型号**：Llama 3 8B 在很多任务上够用。
- **Qwen 系列小型号**：Qwen 2.5 7B 在中文任务上表现出色。

**技术驱动力**：
- **知识蒸馏**（Knowledge Distillation）：用大模型"教"小模型，让小模型学到更有价值的知识。
- **量化**（Quantization）：将模型的 32-bit 浮点参数压缩到 4-bit 或 8-bit，模型大小缩小 4-8 倍，推理速度大幅提升，精度损失极小。
- **剪枝**（Pruning）：移除不重要的参数连接，降低模型复杂度。

### 5.4 2026 年最值得关注的技术方向

| **开源模型能力追赶** | 社区驱动的创新速度超过大厂 | 不依赖 API Key 也能做强大的 AI 应用 |
| **端侧 AI** | 8B 模型在手机上跑出 GPT-4 水平 | 未来很多 AI 功能会直接在设备上运行，隐私更好、延迟更低 |
| **AI 安全与对齐** | 模型越强，安全问题越重要 | 做 AI 应用时必须考虑安全边界、Prompt 注入防御、输出审核 |

**三条临别建议**：

1. **保持 Hand-on**。每周至少写一次代码、跑一次 Agent。AI 领域三个月不碰 = 知识过期。
2. **深入而非泛滥**。不要追每一个新模型、新工具。选一个方向深挖 1000 小时。浅尝 100 个工具不如精通 1 个领域。
3. **拥抱社区，乐于分享**。把你做的东西写出来、发出来。教别人是最好的学习方式，分享会带来意想不到的机会。

- 2017：Transformer 论文发表 → 现代大模型的技术原点
