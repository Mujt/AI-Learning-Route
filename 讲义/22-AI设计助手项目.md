## 三、项目概述

### 3.1 项目定位

**AI Design Assistant（AI设计助手）** 是本课程的综合实践项目（Capstone Project）。学生需要整合前7周学到的所有知识和技能，独立开发一个能够根据用户的设计需求自动生成完整设计方案的AI应用。

该项目的定位是：**一个面向设计专业学生和设计师的智能设计辅助工具**。用户只需输入自然语言描述的设计需求，系统即可自动生成设计提案、概念图提示词、PPT大纲、预算估算和项目时间线等完整的设计文档。

### 3.2 核心功能

```
用户输入设计需求（如"设计一个现代风格咖啡馆"）
                    ↓
        ┌──── 需求分析 Agent ────┐
        │  提取关键设计参数       │
        └────────────────────────┘
                    ↓
    ┌───────────────────────────────────────┐
    │         并行生成（Parallel Generation） │
    ├───────────┬───────────┬───────────────┤
    │ 设计方案  │ 图像提示词 │ PPT大纲        │
    │ Agent    │ Agent     │ Agent         │
    ├───────────┴───────────┴───────────────┤
    │  预算估算 Agent  │  时间线 Agent        │
    └───────────────────────────────────────┘
                    ↓
    ┌───────────────────────────────────────┐
    │         输出组装与展示                  │
    │  设计提案 + 图像Prompt + PPT + 预算 +   │
    │  时间线 → 可导出完整Markdown提案文档     │
    └───────────────────────────────────────┘
```

## 四、核心知识点详解

### 4.1 项目架构设计

#### 4.1.1 整体架构

本项目采用 **"输入→分析→并行生成→输出组装"** 四阶段架构：

```
┌─────────────────────────────────────────────────────────────────┐
│                        AI Design Assistant                       │
├─────────────────────────────────────────────────────────────────┤
│  [1] 输入层 (Input Layer)                                        │
│      ├── 项目基本信息（名称、类型、面积）                          │
│      ├── 目标用户与使用场景                                       │
│      ├── 预算范围与风格偏好                                       │
│      └── 特殊需求与约束条件                                       │
├─────────────────────────────────────────────────────────────────┤
│  [2] 需求分析层 (Analysis Layer)                                 │
│      └── Requirement Analyst Agent: 提取关键参数，输出结构化需求   │
├─────────────────────────────────────────────────────────────────┤
│  [3] 并行生成层 (Parallel Generation Layer)                      │
│      ├── Design Writer Agent: 生成完整设计方案                    │
│      ├── Visual Designer Agent: 生成图像生成提示词                 │
│      ├── PPT Generator Agent: 生成PPT大纲                        │
│      ├── Budget Estimator Agent: 生成预算估算                     │
│      └── Timeline Planner Agent: 生成项目时间线                   │
├─────────────────────────────────────────────────────────────────┤
│  [4] 输出层 (Output Layer)                                       │
│      ├── Tabbed Results Display（Tab页结果展示）                  │
│      ├── Markdown Export（完整提案导出）                          │
│      └── Individual Downloads（各模块独立下载）                   │
└─────────────────────────────────────────────────────────────────┘
```

#### 4.1.2 为什么使用并行生成？

**问题**：如果5个Agent串行调用，每个API调用耗时10-20秒，用户总等待时间 = 50-100秒。

**解决方案**：使用Python的 `concurrent.futures.ThreadPoolExecutor` 实现并行调用，5个Agent同时工作，总等待时间≈最慢的那个Agent的调用时间（约10-20秒），用户体验大幅提升。

```python
# 并行调用的核心代码模式
from concurrent.futures import ThreadPoolExecutor, as_completed

tasks = {
    "design_doc": "generate_design_doc",
    "image_prompts": "generate_image_prompts",
    "ppt_outline": "generate_ppt_outline",
    "budget": "generate_budget",
    "timeline": "generate_timeline",
}

with ThreadPoolExecutor(max_workers=5) as executor:
    futures = {
        executor.submit(generate_func, params): task_name
        for task_name, generate_func in tasks.items()
    }
    for future in as_completed(futures):
        task_name = futures[future]
        results[task_name] = future.result()
```

### 4.2 多Agent协作设计

#### 4.2.1 Agent概念回顾

在本课程第7周，学生学习了Agent的基本概念：Agent是一个具有特定角色、能够自主完成任务的AI实体。在本项目中，我们设计5个专业Agent，每个Agent扮演设计团队中不同角色的职责。

#### 4.2.2 五个专业Agent的职责与Prompt设计

**Agent 1: 需求分析师（Requirement Analyst）**

| 属性 | 内容 |
|------|------|
| **角色定位** | 资深设计项目需求分析师 |
| **输入** | 用户的原始需求文本 |
| **输出** | 结构化的设计需求分析报告，包括功能需求、空间需求、用户需求、风格定位、约束条件 |
| **核心能力** | 从模糊的用户描述中提取关键设计参数，识别隐含需求，发现潜在矛盾 |

**Agent 2: 设计方案撰写师（Design Writer）**

| 属性 | 内容 |
|------|------|
| **角色定位** | 资深建筑/室内/产品设计师 |
| **输入** | 需求分析报告 + 用户原始输入 |
| **输出** | 完整设计方案文档（空间布局、风格说明、材质选择、灯光设计、色彩方案、家具选型、动线规划） |
| **核心能力** | 将抽象需求转化为具体可执行的设计方案，专业术语准确，方案逻辑自洽 |

**Agent 3: 视觉创意设计师（Visual Designer）**

| 属性 | 内容 |
|------|------|
| **角色定位** | AI图像生成提示词专家 |
| **输入** | 设计方案 + 风格偏好 |
| **输出** | 5组高质量的Midjourney/DALL-E图像生成提示词（中英文双语） |
| **核心能力** | 精通图像生成提示词编写技巧（构图、光影、材质、风格、镜头参数、渲染器参数） |

**Agent 4: PPT生成师（PPT Generator）**

| 属性 | 内容 |
|------|------|
| **角色定位** | 资深设计汇报PPT策划师 |
| **输入** | 设计方案 + 预算数据 + 时间线 |
| **输出** | 面向甲方的完整PPT大纲（15-20页），每页含标题、核心内容、配图建议、演讲备注 |
| **核心能力** | 逻辑叙事结构，视觉传达设计，重点突出，说服力强 |

**Agent 5: 预算估算师（Budget Estimator）**

| 属性 | 内容 |
|------|------|
| **角色定位** | 资深工程造价师/预算经理 |
| **输入** | 设计方案 + 面积 + 预算上限 |
| **输出** | 按空间分区/项目阶段的详细预算表，含百分比分析和风险预留 |
| **核心能力** | 成本控制、市场行情判断、预算分配合理性分析 |

#### 4.2.3 Agent间的数据流

```
用户输入
    │
    ▼
需求分析Agent ──── 结构化需求JSON ────┬──► 设计方案Agent
                                      ├──► 视觉设计Agent
                                      ├──► PPT生成Agent
                                      ├──► 预算估算Agent
                                      └──► 时间线Agent
                                              │
                                              ▼
                                    输出组装 → 完整提案
```

> **重要说明**：为了避免总等待时间过长，本项目中的5个生成Agent实际是基于同一个用户输入**并行调用**的。需求分析Agent的结果作为上下文注入到每个生成Agent的Prompt中，但各Agent不互相等待。这种设计在实际项目中更为实用。

### 4.4 设计领域Prompt Engineering

#### 4.4.1 为什么需要领域专用Prompt？

不同设计领域（建筑、室内、产品、UI）的专业术语、评估标准、表述方式差异很大。通用的Prompt模板无法产出符合领域标准的专业输出。因此，本项目为每个设计类型定制了专用Prompt模板。

#### 4.4.2 四种设计类型的Prompt特点

| 设计类型 | 核心关注点 | Prompt关键要素 | 专业术语示例 |
|----------|-----------|---------------|-------------|
| **建筑设计** | 结构安全、空间功能、与环境关系、建筑规范 | 体量、立面、材料、结构体系、日照分析、交通流线 | 容积率、轴网、幕墙、悬挑、中庭 |
| **室内设计** | 空间氛围、人流动线、材质触感、灯光层次 | 空间分区、色彩搭配、灯光设计、家具选型、软装搭配 | 动线、节点、收口、照度、色温 |
| **产品设计** | 人机工程、制造工艺、成本控制、用户体验 | 形态、材质、加工工艺、人机交互、CMF（颜色材质表面处理） | 脱模斜度、分型线、人体工学、CMF |
| **UI设计** | 信息架构、视觉层次、交互逻辑、可用性 | 页面布局、组件设计、交互流程、视觉语言、响应式设计 | 栅格系统、设计令牌、组件库、可访问性 |

#### 4.4.3 设计Prompt的结构化模板

```
你是一位资深的{设计类型}设计师，拥有15年行业经验。

## 项目背景
{用户输入的项目背景信息}

## 设计约束
- 空间面积：{面积}平方米
- 预算上限：{预算}万元
- 目标用户：{目标用户描述}
- 风格偏好：{风格描述}
- 特殊需求：{特殊需求}

## 输出要求
请按照以下章节结构输出完整设计方案：

### 1. 设计理念与概念定位
### 2. 空间布局与功能分区
### 3. {领域特定章节...}
### 4. 材质与色彩方案
### 5. 灯光设计策略
### 6. 家具/元素选型建议
### 7. 设计亮点与创新点

## 格式要求
- 使用专业设计术语，同时确保非专业人士也能理解
- 每个章节不少于300字
- 重要概念用**加粗**标注
- 如有具体尺寸建议，请以毫米（mm）为单位
```

```python
def init_openai_client() -> Optional[openai.OpenAI]:
    """初始化OpenAI兼容的客户端（支持OpenAI、DeepSeek、通义千问等）"""
    api_key = st.session_state.get("api_key", "")
    base_url = st.session_state.get("base_url", "https://api.openai.com/v1")
    model = st.session_state.get("model", "gpt-4o")

    if not api_key:
        st.error("请在侧边栏输入API Key")
        return None

    try:
        client = openai.OpenAI(api_key=api_key, base_url=base_url)
        return client
    except Exception as e:
        st.error(f"API客户端初始化失败: {str(e)}")
        return None


def call_llm(
    client: openai.OpenAI,
    system_prompt: str,
    user_message: str,
    temperature: float = 0.7,
    max_tokens: int = 4096,
    stream_callback=None
) -> str:
    """
    调用大语言模型

    参数:
        client: OpenAI客户端
        system_prompt: 系统提示词（定义角色和行为）
        user_message: 用户消息（具体任务描述）
        temperature: 创造性参数（0=确定性, 1=高创造性）
        max_tokens: 最大输出token数
        stream_callback: 流式输出回调函数（可选）

    返回:
        模型生成的完整文本
    """
    model = st.session_state.get("model", "gpt-4o")

    try:
        if stream_callback:
            # 流式调用
            stream = client.chat.completions.create(
                model=model,
                messages=[
                    {"role": "system", "content": system_prompt},
                    {"role": "user", "content": user_message}
                ],
                temperature=temperature,
                max_tokens=max_tokens,
                stream=True
            )
            full_response = ""
            for chunk in stream:
                if chunk.choices[0].delta.content:
                    delta = chunk.choices[0].delta.content
                    full_response += delta
                    stream_callback(delta)
            return full_response
        else:
            # 普通调用
            response = client.chat.completions.create(
                model=model,
                messages=[
                    {"role": "system", "content": system_prompt},
                    {"role": "user", "content": user_message}
                ],
                temperature=temperature,
                max_tokens=max_tokens
            )
            return response.choices[0].message.content

    except openai.APIError as e:
        return f"❌ API调用失败: {str(e)}"
    except Exception as e:
        return f"❌ 未知错误: {str(e)}"
```

```python
# ==================== 主函数 ====================

def main():
    """AI Design Assistant 主函数"""

    # 初始化Session State
    if "results" not in st.session_state:
        st.session_state["results"] = {}
    if "is_generating" not in st.session_state:
        st.session_state["is_generating"] = False

    # 渲染侧边栏，获取配置
    design_type, selected_options = render_sidebar()

    # 渲染主表单
    project_name, target_users, area, budget, style, special_requirements = render_main_form()

    # ---- 生成按钮 ----
    st.markdown("---")

    col_btn, col_status = st.columns([1, 3])
    with col_btn:
        generate_clicked = st.button(
            "🚀 生成设计方案",
            type="primary",
            use_container_width=True,
            disabled=st.session_state["is_generating"]
        )

    # ---- 执行生成逻辑 ----
    if generate_clicked:
        # 验证输入
        if not st.session_state.get("api_key"):
            st.error("❌ 请在侧边栏输入API Key后再生成")
            return
        if not project_name:
            st.error("❌ 请输入项目名称")
            return
        if not style:
            st.warning("⚠️ 建议输入设计风格偏好以获得更精准的结果")

        st.session_state["is_generating"] = True
        st.session_state["results"] = {}

        # 初始化API客户端
        client = init_openai_client()
        if not client:
            st.session_state["is_generating"] = False
            return

        # 创建进度显示区域
        progress_bar = st.progress(0, "正在初始化...")
        status_text = st.empty()

        # 定义并行任务
        results = {}
        total_tasks = len(selected_options)

        # 第一步：生成设计方案（设计方案是后续模块的基础）
        if "design_doc" in selected_options:
            status_text.info(f"📄 正在生成设计方案...")
            results["design_doc"] = generate_design_doc(
                client, design_type, project_name, target_users,
                area, budget, style, special_requirements
            )
            progress_bar.progress(1 / total_tasks, f"设计方案完成 ({1}/{total_tasks})")

        # 第二步：并行生成其余模块
        remaining_options = [opt for opt in selected_options if opt != "design_doc"]

        if remaining_options:
            design_doc_for_context = results.get("design_doc", "")

            # 定义任务映射
            def create_task(opt_key):
                if opt_key == "image_prompts":
                    return ("🎨 正在生成概念图提示词...",
                            generate_image_prompts(client, design_type, project_name, style, design_doc_for_context))
                elif opt_key == "ppt_outline":
                    return ("📊 正在生成PPT大纲...",
                            generate_ppt_outline(client, design_type, project_name, target_users, style,
                                                 design_doc_for_context, results.get("budget", ""), results.get("timeline", "")))
                elif opt_key == "budget":
                    return ("💰 正在生成预算估算...",
                            generate_budget(client, design_type, project_name, area, budget, style, design_doc_for_context))
                elif opt_key == "timeline":
                    return ("📅 正在生成项目时间线...",
                            generate_timeline(client, design_type, project_name, area, style))
                return ("", "")

            # 并行执行
            completed_count = 1  # 设计方案已完成
            with ThreadPoolExecutor(max_workers=min(len(remaining_options), 5)) as executor:
                future_to_opt = {}
                for opt_key in remaining_options:
                    msg, _ = create_task(opt_key)
                    future = executor.submit(
                        lambda k=opt_key: (k, create_task(k)[1])
                    )
                    future_to_opt[future] = (opt_key, msg)

                for future in as_completed(future_to_opt):
                    opt_key, msg = future_to_opt[future]
                    status_text.info(msg)
                    try:
                        key, result = future.result()
                        results[key] = result
                        completed_count += 1
                        progress_bar.progress(
                            completed_count / total_tasks,
                            f"已完成 {completed_count}/{total_tasks}"
                        )
                    except Exception as e:
                        results[opt_key] = f"❌ 生成失败: {str(e)}"
                        completed_count += 1

        # 更新完成状态
        progress_bar.progress(1.0, "✅ 全部生成完成！")
        status_text.success("🎉 所有模块生成完毕！请在下方Tab页查看结果。")

        st.session_state["results"] = results
        st.session_state["is_generating"] = False

        # 强制刷新以显示结果
        st.rerun()

    # ---- 显示之前生成的结果 ----
    if st.session_state["results"] and not st.session_state["is_generating"]:
        render_results(st.session_state["results"], selected_options)

        # ---- 导出完整提案 ----
        if st.session_state["results"]:
            st.markdown("---")
            col_export1, col_export2 = st.columns([1, 3])

            with col_export1:
                full_proposal = export_full_proposal(
                    project_name if project_name else "未命名项目",
                    design_type,
                    target_users,
                    area,
                    budget,
                    style,
                    special_requirements,
                    st.session_state["results"],
                    selected_options
                )
                st.download_button(
                    label="📥 导出完整提案（Markdown）",
                    data=full_proposal,
                    file_name=f"{project_name or '设计提案'}_{datetime.now().strftime('%Y%m%d_%H%M%S')}.md",
                    mime="text/markdown",
                    use_container_width=True
                )

            with col_export2:
                st.caption(
                    "导出的Markdown文档包含所有已生成的模块内容，"
                    "可以用Typora、VS Code、Notion等工具打开查看和编辑。"
                )

    # ---- 页脚 ----
```

### 5.4 常见问题与解决方案（5分钟）

| 问题 | 可能原因 | 解决方案 |
|------|----------|----------|
| 点击生成按钮无反应 | API Key未填写或格式错误 | 检查侧边栏API Key是否正确 |
| 报错 "Connection Error" | 网络无法访问API或Base URL不对 | 检查网络和Base URL；如使用OpenAI需科学上网，可切换DeepSeek等国内API |
| 生成了内容但Tab页无显示 | `st.session_state` 未正确更新 | 确认代码中 `st.rerun()` 调用正确 |
| 导出文件中某模块显示"未生成" | 该模块未勾选或生成失败 | 检查侧边栏对应的checkbox是否勾选 |
| 生成速度很慢（>2分钟） | 使用了 `gpt-4o` 等慢模型或网络延迟 | 切换为 `gpt-4o-mini` 或 `deepseek-chat` 等更快模型 |
| 预算估算数据明显不合理 | 模型对市场价格了解有限 | 在Prompt中要求更具体的预算参考或手动调整 |
| 图像提示词生成的英文不够专业 | 模型对设计英语术语掌握不足 | 在system_prompt中加入了更多专业术语约束 |

## 八、常见问题（FAQ）

### Q1: 为什么我的代码运行后显示"模块未找到"错误？
**A**: 请确认已正确安装所需依赖。在终端中运行：
```bash
pip install streamlit openai
```
如果使用Anaconda环境，请确保激活了正确的环境。

### Q2: 我没有OpenAI的API Key怎么办？
**A**: 可以使用国内的API替代方案：
- **DeepSeek**：注册地址 https://platform.deepseek.com，新用户有免费额度，模型名填 `deepseek-chat`
- **通义千问**：注册地址 https://dashscope.aliyun.com，有免费额度，模型名填 `qwen-plus`
- **Moonshot (Kimi)**：注册地址 https://platform.moonshot.cn，模型名填 `moonshot-v1-8k`

在侧边栏选择对应的API提供商，填入对应的API Key和Base URL即可。

### Q3: 生成的方案质量不够高怎么办？
**A**: 几个提升输出质量的技巧：
1. **更详细的输入**：在"特殊需求"栏中尽可能详细地描述您的设计意图、功能需求和参考案例
2. **调整Temperature**：在高级设置中将Temperature调低（0.3-0.5），输出会更精确和一致
3. **使用更强的模型**：将模型从 `gpt-4o-mini` 升级到 `gpt-4o` 或 `claude-sonnet-4-20250514`
4. **优化Prompt**：根据自己的专业领域，修改第五部分中的Prompt模板，加入更专业的术语和行业标准

### Q4: 如何将应用部署到互联网让别人也能使用？
**A**: 最简单的方案是使用Streamlit Cloud（免费）：
1. 将代码上传到GitHub仓库（需要包含 `requirements.txt`）
2. 访问 https://share.streamlit.io，用GitHub账号登录
3. 点击 "New app"，选择你的仓库和主文件
4. 在Advanced settings中设置Secrets（如API Key），避免密钥泄露到代码中
5. 点击Deploy即可获得公开链接

### Q5: 能否支持文件上传（如上传现场照片或CAD图纸）？
**A**: 可以。Streamlit提供了 `st.file_uploader` 组件。对于图像文件，可以结合多模态模型（如GPT-4o）进行图像分析后作为设计参考输入。这是一个很好的拓展方向。

### Q6: 本项目的"Agent"和LangGraph中的"Agent"有什么不同？
**A**: 本节课中的Agent是**概念层面**的Agent设计——即通过System Prompt赋予每个调用不同的角色和职责。这是Agent设计的最基础也是最实用的形式。LangGraph等框架提供了更高级的Agent编排能力，包括状态管理、条件路由、工具调用等。第7周学习的Agent概念为本节课奠定了基础，而本节课的实践也将在第8周第2课"多Agent"中进一步深化。

### Q7: 并行生成是否会产生一致性问题（如设计方案的风格与预算估算的风格不匹配）？
**A**: 这是一个很好的问题。由于各Agent是并行的，它们各自独立完成生成，可能在细节上存在不一致。在这个基础版本中，我们通过以下方式缓解此问题：
- 所有Agent使用相同的用户输入参数
- 设计方案的结果作为上下文注入到其他Agent的Prompt中
- 在进阶版本中，可以采用串行+并行的混合模式，先串行生成核心方案，再并行生成衍生内容

### Q8（企业）：这种AI项目看起来成本很低，为什么很多企业还是没做？

**答**：三个主要原因——1) **认知差距**：很多中小企业管理者不知道"几万块就能做一个实用的AI工具"，以为AI都是大厂的事；2) **人才缺失**："会用AI的人"本身就是稀缺资源——这恰好是本课程在解决的问题；3) **惯性阻力**：改变现有工作流需要推动力，需要有人迈出第一步。建议：从最小的试点开始（¥5000以内），做出一个"哇，这个真好用"的示范效果，再推动更大投入。

### Q9（企业）：每个企业都需要自己开发AI应用吗？不能直接买SaaS吗？

**答**：2026年的趋势是：通用场景（客服/营销/简历筛选）有越来越多的AI SaaS可选，应该优先采购。但**差异化场景**——那些直接关系你企业核心竞争力的流程——仍然需要定制开发。本课程项目的价值在于让你理解"一个AI应用是怎么建成的"，这样你在采购SaaS时知道该问什么问题，在需要自建时知道从何入手。
