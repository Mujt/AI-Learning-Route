# 第2周：Python 开发（读懂代码篇）

> **课程定位**：第 2 周核心课程。在零基础前提下，用 **6 小时（3 堂课 × 2 小时）** 建立 Python 代码"阅读能力"，让学员能读懂绝大多数 Python 项目代码（前后端开发、Agent 开发、数据分析脚本……），并在课1 亲手完成一次 **Skills 开发实战**。
> **教学目标**：**读懂基本代码** >> **熟练编写**。不需要熟练编程，但需要能看懂项目里每一行代码在干什么、每个文件的结构是什么、类与函数如何组织；同时具备"把重复任务固化成 Skill"的 AI 协作能力。

---

## 一、教学时间评估（为什么是 3 堂课）

| 评估项 | 结论 |
|--------|------|
| 目标人群 | 零基础大学生（无编程经验，但已会使用 AI 辅助、接触过 Skills 概念） |
| 教学目标 | **读懂基本 Python 代码** + 一次 Skills 开发实战，不要求熟练编写 |
| 内容范围 | Python 基础语法（合并精简）+ Skills 开发实战 + 数据分析 + 项目实战 |
| **建议总课时** | **6 小时（3 堂课 × 2 小时）** |

**为什么从 5 堂压缩到 3 堂**：

```
教学目标定位："读懂基本 Python 代码"（不是"熟练写、不是深研 OOP"）
→ 语法课只需 1 堂（把原课1-3 压缩合并，只保留"认识语法"所需内容）
→ 多出的时间用于 Skills 开发实战（本课程特色，课1后半堂）
→ 数据分析 1 堂、项目阅读实战 1 堂，共 3 堂
```

```
原 5 堂结构（10h）                →  新 3 堂结构（6h）
┌──────────────────────────────┐   ┌──────────────────────────────┐
│ 课1  Python 语法入门          │   │ 课1 Python基础与Skills开发实战 │
│ 课2  函数、模块与文件          │──→│   语法快览(变量/条件/循环/     │
│ 课3  面向对象编程(深化)        │   │   列表/字典/函数/类) +        │
│                              │   │   Skills开发实战(开发技能包)   │
├──────────────────────────────┤   ├──────────────────────────────┤
│ 课4  Python 数据分析          │   │ 课2 Python 数据分析           │
│                              │──→│   NumPy/Pandas/Matplotlib     │
├──────────────────────────────┤   ├──────────────────────────────┤
│ 课5  项目代码阅读实战         │   │ 课3 项目代码阅读实战          │
│                              │──→│   四步法+前后端+Agent 验收     │
└──────────────────────────────┘   └──────────────────────────────┘
```

**设计原则**：
1. **"读懂" ≠ "会写"**：读代码所需知识约为写的 30%。语法课只保留"看到认识、不懂会问、能猜会验"的最小集——变量/类型/条件/循环/列表/字典/函数/import/类/装饰器，一次讲完。
2. **Skills 开发实战 = 本课特色**：第1周学了"用 Skills"，第2周课1 学"做 Skills"——把读代码方法论（翻译→猜输出→验证）固化成 `python-code-reader` 技能包，学以致用、反哺阅读。
3. **深奥内容留给项目**：异常、文件读写、`*args/**kwargs`、继承等细节不单独开课，在课2、课3 读真实代码时"遇到再学"——项目是最好的老师。

## 三、学习目标（毕业要求）

完成本课程后，学员应能够：

1. **读懂基本语法**：能解释任意一段基础 Python 代码（变量、类型、条件、循环、列表、字典、函数、类）的执行结果。
2. **读懂类与对象**：能看懂一个类中 `__init__`、`self`、方法、继承、`@` 装饰器的含义——这是读懂框架与 Agent 代码的关键。
3. **读懂数据处理代码**：能看懂 NumPy 数组操作、Pandas DataFrame 的筛选/分组/聚合、Matplotlib 绘图。
4. **读懂真实项目**：能按照"看结构 → 找入口 → 跟调用链 → 画脑图"的四步法，结合 AI 辅助，读懂一个中等规模 Python 项目并复述其逻辑。
5. **开发一个 Skill**：能独立编写 SKILL.md（描述、执行步骤、示例），把重复性任务固化成 AI 技能包。
6. **AI 协作读代码**：遇到不懂的代码，会用"请用大白话解释这段代码"的模板让 AI 当翻译官，并自己运行验证。

**核心心法**（贯穿 3 堂课）：

> "**读代码像读书**：先看目录（项目结构），再看章节（文件与类），最后精读句子（函数与表达式）。遇到不懂的句子，用 AI 当翻译官，复制代码问它'这行在干什么'。"
> "**不要求背语法，要求查语法**。会查文档、会问 AI、会运行小实验验证——这才是现代开发者的读代码能力。"
> "**会开发 Skills = 会'教学 AI'**。把你最常让 AI 干的事写成技能包，从此一劳永逸。"

## 五、教学方法与 AI 辅助策略

1. **"读代码猜输出"贯穿始终**：每堂课都安排"看代码 → 猜输出 → 运行验证"环节，训练阅读能力而非背诵能力。
2. **AI 当"代码翻译官"**：核心习惯——遇到看不懂的代码，复制给 AI："请用大白话解释这段代码每一行在做什么，我零基础。"本课程所有代码均可如此学习。
3. **"先整体后局部"**：课1 学"零件"，课2 学"应用"，课3 学"整机"。每课结尾预告下一课，形成逻辑链。
4. **Skills 实战重体验**：课1 后半堂是"做中学"——写完技能包立刻测试触发，让学员第一次体验"教 AI 干活"。
5. **排错口诀**：`报错不要慌，复制给AI；问它为什么，再问怎么改`。

## 七、应急预案

| 情况 | 处理方案 |
|------|----------|
| 环境安装耗时过长 | 课1 环境环节压缩为"演示+课后补装"；改用在线 Python 环境（Colab / pythontutor） |
| 学生基础差异大 | 快的学生做"选做挑战题"；慢的学生以"读代码"为主，不要求手写 |
| 语法快览节奏太快 | 三个实操（猜输出）随堂即练即验；没跟上的课后用 AI 补课 |
| Skills 测试不触发 | 检查 SKILL.md 的 `description` 是否写清使用场景；或手动对 AI 说"使用 python-code-reader 技能" |
| 数据分析库装不上 | 提前准备镜像源（清华/阿里 pip 源）；或改用 Colab |
| 课3 项目太长 | 拆分为"教师精读前半 + 学生独立读后半"，按实际情况调整 |
