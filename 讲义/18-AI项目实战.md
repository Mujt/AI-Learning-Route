## 三、项目概述

### 3.1 项目名称

**专业知识问答系统 (Professional Knowledge Q&A System)**

### 3.2 项目背景

企业内部通常沉淀了大量技术文档、操作手册、规章制度等非结构化文本数据。传统的关键词搜索方式无法满足"语义理解"的检索需求——员工需要花费大量时间翻阅文档才能找到答案。本课程项目正是为了解决这一痛点：利用RAG（检索增强生成）技术，构建一个基于私有文档的智能问答系统。

### 3.3 核心业务流程

```
用户上传文档 → 系统解析文本 → 文本分块(Chunking)
       ↓
用户提问 → 语义检索(Retrieval) → 检索相关文本块
       ↓
相关文本块 + 用户问题 → LLM生成答案 → 展示答案并标注引用来源
```

简单来说，系统的工作流程包含六个步骤：

1. **文档上传**：用户通过Web界面上传PDF、TXT或Markdown格式的文档。
2. **文本解析**：系统根据文件类型选择合适的解析器，提取纯文本内容。
3. **文本分块与向量化**：将长文本切分为适合检索的语义块，通过Embedding模型转换为向量。
4. **向量存储**：将向量及其对应的原始文本存储到ChromaDB向量数据库中。
5. **语义检索**：当用户提问时，将问题向量化后在数据库中执行相似度搜索，取回最相关的文本块。
6. **生成回答**：将检索到的文本块作为上下文，与用户问题一起构建Prompt，发送给LLM生成带引用的答案。

### 3.4 技术选型

| 层级 | 技术 | 选型理由 |
|------|------|----------|
| **前端框架** | Streamlit | 纯Python编写，无需前端知识，组件丰富，适合快速搭建数据应用 |
| **向量数据库** | ChromaDB | 轻量级、纯Python、零配置、内置Embedding支持，适合本地部署 |
| **Embedding模型** | sentence-transformers (all-MiniLM-L6-v2) | 开源、轻量（约80MB）、本地运行、无需API费用 |
| **LLM API** | OpenAI兼容接口 | 通用标准，可对接多种模型（DeepSeek、通义千问、OpenAI等） |
| **PDF解析** | PyPDF2 | 纯Python、无需系统依赖、适合大多数PDF文档 |
| **文本分块** | 自实现（基于字符切分+重叠窗口） | 灵活可控，不引入额外依赖 |

**分层职责**：
- **表现层**：负责用户交互，包括文件上传、聊天输入、结果展示。不包含业务逻辑。
- **业务逻辑层**：实现RAG管线的核心流程，是系统的大脑。
- **数据层**：负责数据的持久化存储和外部API调用。

这种分层的优势在于：
- 表现层变化（如改用Gradio）不影响核心逻辑
- 可以独立测试业务逻辑层
- Embedding模型或LLM API可以独立替换

#### 4.4.2 文本处理模块 (M2)

**PDF解析（PyPDF2）**：

```python
def parse_pdf(file_bytes: bytes) -> str:
    """从PDF文件字节流中提取文本"""
    reader = PyPDF2.PdfReader(io.BytesIO(file_bytes))
    text = ""
    for page in reader.pages:
        page_text = page.extract_text()
        if page_text:
            text += page_text + "\n"
    return text
```

**文本分块策略**：

分块（Chunking）是RAG系统中最关键的预处理步骤之一。分块质量直接影响检索效果。

- **块大小 (chunk_size)**：每个文本块的最大字符数。太小则语义不完整，太大则检索精度下降。推荐值：500字符。
- **重叠大小 (chunk_overlap)**：相邻块之间的重叠字符数。用于避免关键信息恰好落在块边界而被切断。推荐值：50字符（约为chunk_size的10%）。
- **高级选项**：使用递归字符分割（先按段落换行符 `\n\n`，再按单个换行符 `\n`，最后按句号、空格切分），可以更智能地识别语义边界。

```python
def chunk_text(text: str, chunk_size: int = 500, chunk_overlap: int = 50) -> list:
    """将长文本切分为重叠的文本块"""
    chunks = []
    start = 0
    text_length = len(text)
    while start < text_length:
        end = start + chunk_size
        chunk = text[start:end]
        chunks.append(chunk)
        start = end - chunk_overlap  # 减去重叠部分，下一块的起点向前挪
    return chunks
```

#### 4.4.3 向量数据库模块 (M3)

**ChromaDB核心概念**：

- **Collection（集合）**：类似关系数据库中的"表"，用于组织和管理一组相关的向量数据。
- **Document（文档）**：原始文本数据。
- **Embedding（嵌入向量）**：文本的数值化向量表示。
- **Metadata（元数据）**：附加的结构化信息，可用于过滤检索结果。

**Embedding模型缓存**：

```python
@st.cache_resource
def load_embedding_model():
    """加载Embedding模型（使用Streamlit缓存，全局只加载一次）"""
    from sentence_transformers import SentenceTransformer
    return SentenceTransformer('all-MiniLM-L6-v2')
```

关键点：使用 `@st.cache_resource` 装饰器缓存模型对象。这确保了：
- 模型只在首次使用时下载和加载
- 后续请求复用已加载的模型实例，显著提升响应速度
- 所有用户共享同一个模型实例（资源级缓存）

**创建/获取Collection**：

```python
import chromadb
from chromadb.config import Settings

def get_or_create_collection(chroma_client, collection_name: str = "knowledge_base"):
    """获取或创建ChromaDB集合"""
    try:
        collection = chroma_client.get_collection(name=collection_name)
    except Exception:
        collection = chroma_client.create_collection(name=collection_name)
    return collection
```

#### 4.4.4 语义检索模块 (M4)

**检索流程**：

1. 将用户查询通过Embedding模型转换为查询向量
2. 在ChromaDB的Collection中执行相似度搜索
3. 返回Top-K个最相关的文档块及其元数据

```python
def retrieve(query: str, collection, embedding_model, k: int = 4) -> list:
    """执行语义检索，返回Top-K相关文档块"""
    query_embedding = embedding_model.encode(query).tolist()
    results = collection.query(
        query_embeddings=[query_embedding],
        n_results=k
    )
    # results 结构: {"ids": [...], "documents": [...], "metadatas": [...], "distances": [...]}
    return results
```

**MMR（最大边际相关性）检索**：

除了基础的相似度检索，ChromaDB还支持获取更多候选结果后自行做MMR重排。MMR在**相关性**和**多样性**之间取得平衡，避免返回高度重复的文档块。

#### 4.4.5 LLM生成模块 (M5)

**RAG Prompt模板**：

```
你是一个专业的知识问答助手。请严格基于以下参考文档的内容回答问题。
如果参考文档中没有足够的信息来回答该问题，请明确告知用户"根据现有文档，我无法回答此问题"，
不要编造任何信息。

参考文档：
{context}

用户问题：{question}

请用中文回答，并在回答末尾列出所引用的文档来源。
```

**Prompt设计原则**：
1. **角色设定**：明确AI的身份和行为边界（"专业的知识问答助手"）
2. **约束条件**：要求严格基于文档回答，禁止编造（防止幻觉）
3. **上下文注入**：将检索到的文档块注入Prompt
4. **格式要求**：指定回答语言和来源引用格式

**流式输出实现**：

```python
def generate_stream(prompt: str, api_key: str, model: str, base_url: str):
    """调用LLM API并流式返回结果"""
    from openai import OpenAI
    client = OpenAI(api_key=api_key, base_url=base_url)
    
    response = client.chat.completions.create(
        model=model,
        messages=[{"role": "user", "content": prompt}],
        stream=True,
        temperature=0.7,
        max_tokens=1024
    )
    
    for chunk in response:
        if chunk.choices[0].delta.content:
            yield chunk.choices[0].delta.content
```

```python
# 专业知识问答系统 (Professional Knowledge Q&A System)
# 基于RAG技术，支持PDF/TXT/MD文档上传、向量检索、LLM生成回答

# ============================================================================
# 0. 初始化配置
# ============================================================================

load_dotenv()

# 页面配置：这是Streamlit的全局配置，必须在任何st.xxx调用之前设置
st.set_page_config(
    page_title="专业知识问答系统",
    page_icon="📚",

    initial_sidebar_state="expanded"       # 侧边栏默认展开

# ============================================================================
# 1. 文本解析模块 (M2)
# ============================================================================

def parse_pdf(file_bytes: bytes) -> str:
    """
    解析PDF文件，提取纯文本内容。
    
    参数:
        file_bytes: PDF文件的字节流
    
    返回:
        提取到的文本字符串。如果PDF为扫描版（图片PDF），则返回空字符串。
    
    注意:
        PyPDF2无法从图片中提取文字，如需OCR功能可使用pytesseract。
    """
    try:
        # 将字节流包装为BytesIO，使PyPDF2可以像读取文件一样读取
        reader = PyPDF2.PdfReader(io.BytesIO(file_bytes))
        text_parts = []

        # 逐页提取文本
        for i, page in enumerate(reader.pages):
            page_text = page.extract_text()
            if page_text and page_text.strip():
                text_parts.append(page_text.strip())

        extracted_text = "\n\n".join(text_parts)

        if not extracted_text:
            st.warning("PDF文件可能为扫描版（图片），无法提取文字。建议使用OCR预处理。")

        return extracted_text

    except Exception as e:
        st.error(f"PDF解析失败: {str(e)}")
        return ""


def parse_txt(file_bytes: bytes) -> str:
    """
    解析TXT文件。尝试多种编码以确保正确读取中文内容。
    
    参数:
        file_bytes: TXT文件的字节流
    
    返回:
        解析后的文本字符串
    """
    # 按优先级尝试不同的编码格式
    encodings = ['utf-8', 'gbk', 'gb2312', 'gb18030', 'latin-1']
    for encoding in encodings:
        try:
            return file_bytes.decode(encoding)
        except (UnicodeDecodeError, UnicodeError):
            continue
    
    # 如果所有编码都失败，使用utf-8并忽略无法解码的字符
    return file_bytes.decode('utf-8', errors='ignore')


def parse_md(file_bytes: bytes) -> str:
    """
    解析Markdown文件。
    Markdown本质上是纯文本，直接按TXT方式处理即可。
    （如果需要在UI中渲染Markdown，可以使用st.markdown()）
    
    参数:
        file_bytes: Markdown文件的字节流
    
    返回:
        解析后的文本字符串（保留原始Markdown格式）
    """
    # Markdown文件直接作为文本解析
    return parse_txt(file_bytes)


def parse_document(file_bytes: bytes, filename: str) -> str:
    """
    根据文件扩展名选择对应的解析器。
    
    参数:
        file_bytes: 文件的字节流
        filename: 文件名（用于判断扩展名）
    
    返回:
        解析后的纯文本字符串
    """
    ext = Path(filename).suffix.lower()

    if ext == '.pdf':
        return parse_pdf(file_bytes)
    elif ext == '.txt':
        return parse_txt(file_bytes)
    elif ext == '.md':
        return parse_md(file_bytes)
    else:
        raise ValueError(f"不支持的文件格式: {ext}")

# 2. 文本分块模块 (M2)
# ============================================================================

def chunk_text(
    text: str,
    chunk_size: int = 500,
    chunk_overlap: int = 50
) -> List[str]:
    """
    将长文本切分为具有重叠的文本块（Chunk）。
    
    核心设计思想:
    - chunk_size决定了每个文本块的"视野"大小
    - chunk_overlap确保跨块边界的语义信息不会丢失
    - 简单滑动窗口策略，每步移动 (chunk_size - chunk_overlap) 个字符
    
    参数:
        text: 待分块的原始文本
        chunk_size: 每个块的最大字符数（默认500）
        chunk_overlap: 相邻块之间的重叠字符数（默认50）
    
    返回:
        文本块列表
    
    注意:
        这是一个基础版本的分块器，仅按字符数切分。
        高级版本应使用递归字符分割（RecursiveCharacterTextSplitter），
        优先在段落、句子边界处切分，以获得更好的语义连贯性。
    """
    if not text or not text.strip():
        return []

    chunks = []
    text_length = len(text)
    step = chunk_size - chunk_overlap  # 每次滑动步长

    if step <= 0:
        # chunk_overlap不能大于或等于chunk_size
        step = chunk_size

    start = 0
    while start < text_length:
        end = min(start + chunk_size, text_length)
        chunk = text[start:end].strip()
        if chunk:
            chunks.append(chunk)
        start += step

    return chunks


def generate_chunk_id(source_file: str, chunk_index: int) -> str:
    """
    为每个文本块生成唯一的标识符。
    使用MD5哈希确保ID的唯一性和可重现性。
    
    参数:
        source_file: 源文件名
        chunk_index: 块在文件中的序号
    
    返回:
        唯一的块ID字符串
    """
    identifier = f"{source_file}::chunk_{chunk_index}"
    return hashlib.md5(identifier.encode()).hexdigest()

def add_documents_to_collection(
    collection,
    chunks: List[str],
    chunk_ids: List[str],
    metadatas: List[Dict[str, Any]],
    embedding_model
) -> bool:
    """
    将文本块添加到ChromaDB集合中。
    
    参数:
        collection: ChromaDB集合
        chunks: 文本块列表
        chunk_ids: 块ID列表
        metadatas: 元数据列表（每个元素对应一个文本块的元信息）
        embedding_model: Embedding模型
    
    返回:
        添加是否成功
    
    注意:
        - ChromaDB会自动对documents进行向量化（调用我们传入的embedding_function时则需要手动编码）
        - 这里我们手动编码后传入，以便更灵活地控制embedding过程
        - 使用upsert而非add可以避免重复添加（相同ID会更新而非报错）
    """
    try:
        # 批量计算所有文本块的向量
        embeddings = embedding_model.encode(chunks).tolist()

        # 将数据添加到集合（upsert = update + insert）
        collection.upsert(
            ids=chunk_ids,
            embeddings=embeddings,
            documents=chunks,
            metadatas=metadatas
        )
        return True
    except Exception as e:
        st.error(f"文档添加到向量数据库失败: {str(e)}")
        return False


def clear_collection(collection) -> bool:
    """
    清空集合中的所有数据。
    
    参数:
        collection: ChromaDB集合
    
    返回:
        操作是否成功
    """
    try:
        # 获取所有文档的ID然后删除
        all_ids = collection.get()['ids']
        if all_ids:
            collection.delete(ids=all_ids)
        return True
    except Exception as e:
        st.error(f"清空知识库失败: {str(e)}")
        return False


def get_collection_stats(collection) -> Dict[str, Any]:
    """
    获取集合的统计信息。
    
    参数:
        collection: ChromaDB集合
    
    返回:
        包含文档数量等信息的字典
    """
    try:
        data = collection.get()
        total_chunks = len(data['ids']) if data['ids'] else 0

        # 获取唯一文件源数量
        unique_sources = set()
        if data['metadatas']:
            for meta in data['metadatas']:
                if meta and 'source' in meta:
                    unique_sources.add(meta['source'])

        return {
            "total_chunks": total_chunks,
            "total_documents": len(unique_sources),
            "sources": list(unique_sources)
        }
    except Exception as e:
        return {"total_chunks": 0, "total_documents": 0, "sources": [], "error": str(e)}

def retrieve_relevant_chunks(
    query: str,
    collection,
    embedding_model,
    top_k: int = 4,
    use_mmr: bool = False,
    mmr_lambda: float = 0.5
) -> Dict[str, Any]:
    """
    从向量数据库中检索与查询最相关的文本块。
    
    参数:
        query: 用户查询文本
        collection: ChromaDB集合
        embedding_model: Embedding模型实例
        top_k: 返回的文档块数量
        use_mmr: 是否使用MMR（最大边际相关性）策略
        mmr_lambda: MMR参数，0=最大多样性，1=最大相关性
    
    返回:
        包含检索结果的字典:
        {
            "ids": [...],
            "documents": [...],
            "metadatas": [...],
            "distances": [...]
        }
    
    MMR说明:
        - MMR (Maximum Marginal Relevance) 在相关性和多样性之间平衡
        - lambda值越大，越偏向相关性；越小，越偏向多样性
        - 适合需要覆盖不同角度的检索场景
    """
    # 将查询文本转化为向量
    query_embedding = embedding_model.encode(query).tolist()

    # 执行检索
    if use_mmr:
        # MMR方式：先获取更多候选，然后通过算法筛选
        fetch_k = top_k * 4  # 先获取4倍数量的候选
        results = collection.query(
            query_embeddings=[query_embedding],
            n_results=top_k,
            # ChromaDB原生MMR需要安装chromadb的0.4.x版本以上
            # 这里使用基础相似度查询，再在应用层做MMR
        )
    else:
        # 标准相似度检索
        results = collection.query(
            query_embeddings=[query_embedding],
            n_results=top_k
        )

    return results


def format_retrieval_context(results: Dict[str, Any]) -> str:
    """
    将检索结果格式化为适合LLM的上下文文本。
    
    参数:
        results: retrieve_relevant_chunks的返回结果
    
    返回:
        格式化后的上下文字符串
    """
    if not results.get('documents') or not results['documents'][0]:
        return "（知识库中暂无相关内容）"

    context_parts = []
    documents = results['documents'][0]       # 二维列表: [[doc1, doc2, ...]]
    metadatas = results['metadatas'][0]        # 二维列表: [[meta1, meta2, ...]]
    
    for i, doc in enumerate(documents):
        # 提取来源信息
        source = metadatas[i].get('source', '未知来源') if metadatas else '未知来源'
        context_parts.append(
            f"【文档{i+1}】来源: {source}\n{doc}\n"
        )

    return "\n---\n".join(context_parts)

def build_rag_prompt(context: str, question: str) -> str:
    """
    构建RAG增强的Prompt模板。
    
    设计思路:
    1. 角色设定：明确告知LLM它的角色和行为规范
    2. 上下文注入：将检索到的相关文档内容嵌入Prompt
    3. 约束条件：禁止幻觉，要求基于文档回答
    4. 格式要求：中文回答 + 来源引用
    
    参数:
        context: 检索到的相关文档上下文
        question: 用户的问题
    
    返回:
        完整的Prompt字符串
    """
    prompt = f"""你是一个专业的知识问答助手。你的任务是严格基于以下参考文档的内容来回答用户的问题。

## 行为准则
1. **仅基于参考文档回答**：你的所有回答必须基于下面提供的"参考文档"内容。
2. **禁止编造信息**：如果参考文档中没有足够的信息来回答该问题，请明确告知用户"根据现有文档，我无法回答此问题。请尝试上传更多相关文档或换个方式提问。"，绝对不要编造、推测或使用外部知识。
3. **引用来源**：在回答中引用参考文档的具体内容时，请注明来源（如"根据文档1..."）。
4. **回答语言**：请使用中文回答。

## 参考文档
{context}

## 用户问题
{question}

## 回答
请基于以上参考文档，用中文回答用户的问题，并注明信息来源："""
    return prompt


def generate_answer_stream(
    prompt: str,
    api_key: str,
    base_url: str,
    model: str,
    temperature: float = 0.7,
    max_tokens: int = 1024
):
    """
    调用LLM API生成流式回答。
    
    参数:
        prompt: 完整的RAG Prompt
        api_key: API密钥
        base_url: API基础URL
        model: 模型名称
        temperature: 生成温度（0-2，越高越随机）
        max_tokens: 最大生成token数
    
    Yields:
        每次yield一个文本片段（streaming chunk）
    
    流式输出优势:
        - 用户体验更好（逐字显示，无需等待完整生成）
        - 类似ChatGPT的打字效果
    """
    try:
        # 初始化OpenAI客户端
        client = OpenAI(
            api_key=api_key,
            base_url=base_url
        )

        # 发起流式请求
        response = client.chat.completions.create(
            model=model,
            messages=[
                {"role": "system", "content": "你是一个严谨、专业的知识问答助手。"},
                {"role": "user", "content": prompt}
            ],
            stream=True,              # 开启流式输出
            temperature=temperature,
            max_tokens=max_tokens
        )

        # 逐块返回生成内容
        for chunk in response:
            if chunk.choices[0].delta.content is not None:
                yield chunk.choices[0].delta.content

    except Exception as e:
        yield f"\n\n**错误: LLM API调用失败**\n\n可能原因：\n1. API Key无效或已过期\n2. 网络连接问题\n3. Base URL配置错误\n4. 账户余额不足\n\n详细信息: `{str(e)}`"

                if fname in st.session_state.processed_files:
                    st.write(f"⏭️ {fname} - 已处理，跳过")
                    continue
                
                try:
                    # Step 1: 解析文档
                    st.write(f"📖 正在解析: {fname}...")
                    file_bytes = uploaded_file.getvalue()
                    text = parse_document(file_bytes, fname)
                    
                    if not text or not text.strip():
                        st.write(f"⚠️ {fname} - 未能提取到文本内容，跳过")
                        continue
                    
                    st.write(f"   ├─ 解析完成: {len(text)} 字符")
                    
                    # Step 2: 文本分块
                    chunks = chunk_text(text, chunk_size, chunk_overlap)
                    st.write(f"   ├─ 分块完成: {len(chunks)} 个文本块")
                    
                    # Step 3: 生成块ID和元数据
                    for j, chunk in enumerate(chunks):
                        chunk_id = generate_chunk_id(fname, j)
                        all_ids.append(chunk_id)
                        all_chunks.append(chunk)
                        all_metadatas.append({
                            "source": fname,
                            "chunk_index": j,
                            "char_count": len(chunk)
                        })
                    
                    st.session_state.processed_files.append(fname)
                    processed_count += 1
                    st.write(f"   └─ ✅ {fname} 处理完成！")
                    
                except Exception as e:
                    st.write(f"   └─ ❌ {fname} 处理失败: {str(e)}")
            
            # Step 4: 将文本块添加到向量数据库
            if all_chunks:
                st.write(f"🧮 正在向量化并存储 {len(all_chunks)} 个文本块...")
                
                success = add_documents_to_collection(
                    collection, all_chunks, all_ids, all_metadatas, embedding_model
                )
                
                if success:
                    st.session_state.kb_ready = True
                    status.update(label=f"✅ 处理完成！共处理 {processed_count} 个文档，{len(all_chunks)} 个文本块", state="complete")
                    st.toast(f"🎉 成功添加 {len(all_chunks)} 个文本块到知识库！", icon="✅")
                else:
                    status.update(label="❌ 向量存储失败，请检查Embedding模型是否正常加载", state="error")
            else:
                if processed_count == 0:
                    status.update(label="ℹ️ 没有新的文档需要处理", state="complete")
                else:
                    status.update(label="⚠️ 所有文档均未能成功解析", state="error")
    
    st.divider()
    
    # ---- 对话区 ----
    st.header("💬 第二步：提问")
    
    if not st.session_state.kb_ready:
        # 检查知识库是否已有数据
        stats = get_collection_stats(collection)
        if stats['total_chunks'] > 0:
            st.session_state.kb_ready = True
    
    if not st.session_state.kb_ready:
        st.warning("⚠️ 请先上传并处理文档，构建知识库后再提问。")
        return
    
    # 显示知识库就绪状态
    stats = get_collection_stats(collection)
    st.success(f"✅ 知识库就绪 | 包含 {stats['total_documents']} 个文档、{stats['total_chunks']} 个文本块")
    
    # 渲染历史对话
    for msg in st.session_state.chat_history:
        with st.chat_message(msg["role"]):
            st.markdown(msg["content"])
            # 如果该消息有引用来源，用expander展示
            if msg.get("sources"):
                with st.expander("📎 查看引用来源"):
                    st.text(msg["sources"])
    
    # 用户输入区（chat_input固定在底部）
    user_query = st.chat_input("请输入您的问题，系统将从知识库中检索相关内容并回答...")
    
    if user_query:
        # Step 1: 显示用户消息
        with st.chat_message("user"):
            st.markdown(user_query)
        st.session_state.chat_history.append({"role": "user", "content": user_query})
        
        # Step 2: 检索相关上下文
        with st.spinner("🔍 正在检索知识库..."):
            results = retrieve_relevant_chunks(
                query=user_query,
                collection=collection,
                embedding_model=embedding_model,
                top_k=top_k
            )
            context = format_retrieval_context(results)
        
        # Step 3: 构建Prompt并生成回答
        rag_prompt = build_rag_prompt(context, user_query)
        
        # Step 4: 流式生成并展示回答
        with st.chat_message("assistant"):
            # 创建一个空的占位符，用于流式更新回答
            response_placeholder = st.empty()
            
            try:
                full_response = ""
                for text_chunk in generate_answer_stream(
                    prompt=rag_prompt,
                    api_key=api_key,
                    base_url=base_url,
                    model=model,
                    temperature=temperature
                ):
                    full_response += text_chunk
                    # 实时更新占位符内容
                    response_placeholder.markdown(full_response + "▌")
                
                # 生成完成，移除光标符号
                response_placeholder.markdown(full_response)
                
            except Exception as e:
                response_placeholder.error(f"生成回答时出错: {str(e)}")
                full_response = f"*生成失败: {str(e)}*"
            
            # 展示引用来源
            with st.expander("📎 查看检索到的参考文档"):
                st.text(context)
                # 以表格形式展示检索结果摘要
                if results.get('documents') and results['documents'][0]:
                    for i, (doc, meta) in enumerate(
                        zip(results['documents'][0], results['metadatas'][0])
                    ):
                        source = meta.get('source', '未知')
                        distance = None
                        if results.get('distances') and results['distances'][0]:
                            distance = results['distances'][0][i]
                        
                        st.write(f"**#{i+1}** | 来源: `{source}` | "
                                 f"{'距离: '+f'{distance:.4f}' if distance is not None else ''}")
                        st.text(f"{doc[:200]}..." if len(doc) > 200 else doc)
        
        # 保存助手回复到对话历史
        st.session_state.chat_history.append({
            "role": "assistant",
            "content": full_response,
            "sources": context
        })
```

### 5.4 常见问题与解决方案

#### 问题1：Embedding模型下载失败

**现象**：启动时卡在"加载Embedding模型"步骤，或报网络连接错误。

**原因**：HuggingFace在国内访问不稳定。

**解决方案**：
```python
# 方案A：设置HuggingFace镜像环境变量
# Linux/Mac:
export HF_ENDPOINT=https://hf-mirror.com
# Windows (CMD):
set HF_ENDPOINT=https://hf-mirror.com

# 方案B：手动下载模型到本地
# 1. 访问 https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2
# 2. 下载所有文件到本地目录，如 ./models/all-MiniLM-L6-v2/
# 3. 修改加载代码：
model = SentenceTransformer('./models/all-MiniLM-L6-v2')
```

#### 问题2：PDF中文乱码

**现象**：上传中文PDF后提取出的文本是乱码。

**原因**：某些PDF生成工具使用非标准字体编码。

**解决方案**：
```python
# 方案A：改用pdfplumber（对中文支持更好）
# pip install pdfplumber
import pdfplumber

def parse_pdf_v2(file_bytes: bytes) -> str:
    text_parts = []
    with pdfplumber.open(io.BytesIO(file_bytes)) as pdf:
        for page in pdf.pages:
            text = page.extract_text()
            if text:
                text_parts.append(text)
    return "\n\n".join(text_parts)

# 方案B：使用PyMuPDF (fitz)
# pip install PyMuPDF
import fitz

def parse_pdf_v3(file_bytes: bytes) -> str:
    doc = fitz.open(stream=file_bytes, filetype="pdf")
    text = ""
    for page in doc:
        text += page.get_text()
    return text
```

#### 问题3：回答中出现幻觉（编造信息）

**现象**：AI的回答引用了文档中不存在的内容。

**原因**：Prompt约束不够强，或检索到的上下文不相关。

**解决方案**：
- 强化Prompt中的约束措辞（多次强调"禁止编造"）
- 增大ChromaDB的`top_k`值，确保检索到足够上下文
- 降低temperature（推荐0.3-0.5），减少随机性
- 在Prompt末尾加上："如果你不确定，请直接说'我不确定'"

#### 问题4：ChromaDB数据被意外清空

**现象**：重启应用后知识库数据丢失。

**原因**：`persist_directory`路径在每次运行时动态变化。

**解决方案**：
```python
# 使用固定的绝对路径
PERSIST_DIR = os.path.join(os.path.dirname(os.path.abspath(__file__)), "chroma_db")
os.makedirs(PERSIST_DIR, exist_ok=True)
chroma_client = chromadb.PersistentClient(path=PERSIST_DIR)
```

#### 问题5：Streamlit每次rerun都重新处理文档

**现象**：用户每次交互都触发文档重新处理。

**原因**：文件处理逻辑未使用session_state追踪状态。

**解决方案**：
```python
# 通过processed_files记录已处理的文件（已在代码中实现）
if fname in st.session_state.processed_files:
    st.write(f"⏭️ {fname} - 已处理，跳过")
```

## 八、常见问题（FAQ）

**Q1: 为什么选择Streamlit而不是Gradio？**

Streamlit的优势在于：
- 更原生的Python开发体验（无需额外的block/interface概念）
- 更好的状态管理（st.session_state）
- 更丰富的官方组件（chat_message、chat_input等原生聊天组件）
- 更适合数据密集型应用

Gradio的优势在于：更简单的部署方式、内置的模型分享功能。两者都是优秀的Python Web框架，可根据项目需求选择。

**Q2: chunk_size和chunk_overlap如何选择？**

有多个经验法则：
- chunk_size: 建议 256-1024 字符。中文文档推荐 500 字符（约为250-400个token）
- chunk_overlap: 建议 chunk_size 的 10%-20%，即 50-200 字符
- 文档内容密集（如法律条文）：用更小的chunk_size（256-384）
- 文档内容叙述性强（如教程）：用更大的chunk_size（768-1024）
- 最佳实践：针对你的具体文档做实验，比较不同参数的检索效果

**Q3: Embedding模型的向量维度影响什么？**

- 维度越高，向量能编码的语义信息越多（理论上），但存储和计算成本也越高
- 384维（all-MiniLM-L6-v2）：适合轻量级应用，速度快
- 768维（常见于BERT系列）：中等规模，平衡了效果和速度
- 1024-1536维（大模型如bge-large、OpenAI ada-002）：效果最佳，但需要更多存储和计算资源

**Q4: 这套系统可以用于生产环境吗？**

原型版本适合内部测试和小规模使用。生产化需要额外考虑：
- 使用更高效的分块策略（递归字符分割）
- 添加用户认证和权限管理
- 使用生产级向量数据库（Milvus/Qdrant）
- 添加缓存层（答案缓存、查询缓存）
- 实现异步处理和任务队列
- 添加监控和日志系统

**Q5: 如何处理超大文档（几百页PDF）？**

- 分批处理：一次处理N页，避免内存溢出
- 使用更激进的分块策略
- 考虑使用Map-Reduce模式的摘要：先对每个大段落做摘要，再基于摘要做检索
- 使用文档层级索引（如LlamaIndex的Tree Index）
