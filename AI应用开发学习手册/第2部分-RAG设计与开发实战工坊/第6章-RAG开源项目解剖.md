## 6.1 三大开源 RAG 项目总览

| 项目 | 定位 | 核心技术特色 | 适合人群 |
|------|------|--------------|----------|
| **RAGFlow** | 深度文档理解 RAG 引擎 | 基于深度文档解析（DeepDoc），"引文溯源"式回答 | 文档密集型、对准确率要求高的企业 |
| **FastGPT** | 知识库 + 工作流可视化平台 | 简易编排 + 强大的知识库管理 + 商业化成熟 | 中小企业、想快速搭建知识问答 |
| **Dify** | LLM 应用开发平台 | 可视化编排、Agent、模型管理、RAG 一体 | 应用开发者、产品团队 |

> 三者的本质区别：**RAGFlow 重"文档理解"，FastGPT 重"知识库运营"，Dify 重"应用全生命周期"**。

## 6.2 RAGFlow 深度解析

### 6.2.1 核心定位

RAGFlow 是 InfiniFlow 开源的 RAG 引擎，主打**"DeepDoc 深度文档理解" + "可追溯引用"**，专治复杂文档（扫描件、表格、多栏排版、手写）检索不准的顽疾。

### 6.2.2 技术架构

```
文档输入 → DeepDoc 文档解析引擎
            ├── OCR（扫描件识别）
            ├── 版面分析（Layout）
            ├── 表格识别（Table Structure）
            └── 公式/图表理解
        → 文本分块（结构化保留） → 向量化 → 混合检索 → LLM 生成（强制引用）
```

### 6.2.3 三大核心特色

1. **DeepDoc 深度文档理解**：开源可训练，支持版面分析、表格结构还原、公式提取，对复杂 PDF 解析效果行业领先。
2. **引文溯源（Cite-as-you-answer）**：生成的每句话都关联原文片段，鼠标悬停可见引用来源，**可审计性极强**。
3. **模板化分块（Template-based chunking）**：按文档结构（标题层级）切分，保留章节语义。

### 6.2.4 快速部署

```bash
# Docker Compose 一键部署
git clone https://github.com/infiniflow/ragflow.git
cd ragflow/docker
# 修改 .env 中模型配置（支持 OpenAI 兼容接口 / DeepSeek / 通义等）
docker compose up -d
# 访问 http://localhost:80  配置模型与知识库
```

## 6.3 FastGPT 深度解析

### 6.3.1 核心定位

FastGPT 是"开箱即用的 AI 知识库 + 工作流"平台，主打**低门槛 + 流程编排 + 完整商业化**。

### 6.3.2 核心能力

| 模块 | 能力 |
|------|------|
| 知识库 | 多格式导入、QA 拆分、向量检索 + 全文检索、测试集调优 |
| 工作流 | 拖拽式节点编排（输入/检索/LLM/分支/循环/HTTP 请求） |
| 应用发布 | 一键生成分享链接、嵌入网站、企业微信/钉钉/飞书接入 |
| 商业化 | 计费系统、用户管理、用量统计（社区版具备） |
| 多模型 | 支持 OpenAI、DeepSeek、通义、Ollama 等 |

### 6.3.3 知识库运营亮点

- **QA 拆分**：自动将长文本拆成"问-答"对，检索命中更精准。
- **检索策略可视化调优**：调整检索方式、相似度阈值，用测试集实时看效果。
- **多知识库协同**：一次问答可跨多个知识库检索。

### 6.3.4 部署方式

- **Docker 部署**：`docker-compose up -d`（自带 MongoDB、PostgreSQL、OneAPI）。
- **SaaS 版**：fastgpt.in 快速体验。

## 6.4 Dify 深度解析

### 6.4.1 核心定位

Dify 是**"LLMOps"应用开发平台**：可视化编排从 Prompt 到 Agent、RAG、插件、监控的完整链路，且支持 API 化集成。

### 6.4.2 核心能力

| 模块 | 能力 |
|------|------|
| 应用类型 | 聊天助手、Agent、Text2SQL、工作流、RAG 应用 |
| 工作流编排 | 画布式拖拽 + 节点丰富（LLM/知识检索/条件分支/代码节点/工具） |
| Agent 能力 | Function Calling 插件体系、上百个现成工具插件 |
| RAG 能力 | 文档分段、父子分块、多路召回、重排序（可接 bge-reranker） |
| 模型管理 | 统一接入 OpenAI、DeepSeek、通义、本地 Ollama |
| 观测运维 | 日志、标注、调试、Prompt 管理、API Key 治理 |
| 发布 | WebApp、API 服务、嵌入 SDK |

### 6.4.3 一句话总结

- 追求 **RAG 文档理解极致** → RAGFlow
- 追求 **知识库问答快速上线** → FastGPT
- 追求 **复杂 Agent/工作流应用平台** → Dify

## 6.6 企业级 RAG 平台实战部署（选型案例）

**案例：某制造业企业构建"设备维修知识库"**

| 需求 | 方案 |
|------|------|
| 大量扫描版设备手册（PDF/图纸） | 选 RAGFlow（DeepDoc 深度解析 + OCR） |
| 维修工希望回答"引用原文页码" | RAGFlow 引文溯源天然满足 |
| 后续要接入微信小程序 | Dify 发布 API + 渠道集成 |
| 数据不出内网 | Docker 私有化部署 + 本地模型（Ollama/Qwen） |

**生产部署要点**：
1. 高可用：Nginx 负载均衡 + 多副本 + 数据库独立部署。
2. 模型接入：先接 API（DeepSeek/通义），数据敏感再切本地开源模型。
3. 权限隔离：多租户知识库隔离 + 用户权限管理。
4. 备份：知识库索引 + 数据库定时备份。
5. 监控：接入日志（ELK/Loki）+ 指标（Prometheus）。

## 常见问题（FAQ）

**Q1：这些开源平台和自己写 LangChain 代码有什么区别？**
A：平台把检索、编排、运维（日志、计费、发布）全部封装好了，适合快速交付；自研代码灵活度更高、可控性更强。实践中可"平台做原型，代码做定制"。

**Q2：会不会被开源项目"卡脖子"？**
A：三个项目均提供 API 与数据库标准接口，底层模型、向量库可替换。关键数据与模型不绑定平台，风险可控。

**Q3：三个平台能同时用吗？**
A：可以。例如 RAGFlow 负责难文档解析（通过 API 输出结构化分块），Dify 负责应用编排，FastGPT 负责 C 端知识库运营，各取所长。
