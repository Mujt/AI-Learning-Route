# 第 9 章 大模型典型应用案例

## 学习目标

- 通过医疗病历生成案例掌握"微调 + RAG + 合规"的综合应用
- 通过企业知识问答系统案例掌握"部署 + 服务 + 运营"全链路
- 建立"场景 → 技术选型 → 落地 → 评估"的方法论

## 9.1 案例一：医疗病历生成系统

### 9.1.1 业务背景与痛点

医生每天花 30% 时间写病历，内容重复、格式繁琐。目标：医生口述要点 → 系统自动生成结构化病历，医生审核修改后落库。

**核心约束**：
- 医学准确性要求极高（错误可能导致医疗事故）
- 必须符合病历书写规范（格式、术语、签名要求）
- 数据极其敏感（患者隐私受法律保护）
- 输出必须可追溯可审计

### 9.1.2 技术方案

| 模块 | 方案 | 理由 |
|------|------|------|
| 模型 | 开源模型私有化（Qwen2.5-14B） | 数据不出院、可定制 |
| 微调 | QLoRA 微调（医疗病历风格 + 科室术语） | 学会病历格式与专业表达 |
| 知识增强 | RAG（诊疗指南 + 科室历史病历模板库） | 引用规范、保持一致性 |
| 结构化输出 | 提示词限定 JSON Schema + 后处理校验 | 保证字段完整 |
| 校验 | 规则引擎（必填项、长度、敏感词）+ 医生审核 | 双保险 |
| 审计 | 全量操作日志 + 版本留痕 | 合规要求 |

### 9.1.3 核心流程

```
医生口述/录音转写 → 结构化病历生成（RAG + 微调模型）
→ 字段完整性校验（缺项提示） → 医生在线审核修改
→ 提交签名（电子签名） → 归档 + 审计
```

### 9.1.4 关键实现

**1. 微调数据准备**（2000-5000 条脱敏历史病历）

```json
{
  "instruction": "根据以下问诊信息生成标准门诊病历",
  "input": "患者男，45岁，主诉头痛3天。现病史：...",
  "output": "主诉：头痛3天\n现病史：患者于3天前无明显诱因出现头痛...\n既往史：高血压病史5年...\n诊断：偏头痛\n处理意见：..."
}
```

**2. 生成后结构化校验**

```python
import jsonschema

SCHEMA = {
    "type": "object",
    "required": ["chief_complaint", "present_illness", "diagnosis"],
    "properties": {
        "chief_complaint": {"type": "string", "minLength": 5},
        "present_illness": {"type": "string", "minLength": 20},
        "diagnosis": {"type": "string"},
    }
}
jsonschema.validate(generated_record, SCHEMA)   # 不通过则重新生成/人工处理
```

### 9.1.5 效果与评估

| 指标 | 结果参考 |
|------|----------|
| 病历生成完整性 | 字段完整率 > 95% |
| 医生采纳率（直接使用/少量修改） | 60-80% |
| 病历书写耗时 | 下降 50-70% |
| 医疗差错（AI 生成误导） | 必须为 0（人工审核兜底） |

**合规红线**：AI 只做"草稿"，**最终医疗责任永远在医生**——产品设计与提示词中明确标注"AI 辅助，需医生审核"。

## 9.2 案例二：企业知识问答系统

### 9.2.1 业务背景与痛点

大型制造企业积累海量内部文档（产品手册、SOP、质量规范、合同），员工检索困难、信息孤岛。目标：**统一入口，即问即答，答案有据可查**。

### 9.2.2 技术方案（综合第 2/4 部分全部能力）

```
┌────────────────────────────────────────────┐
│ 前端：员工门户 / 企业微信 / 移动端           │
├────────────────────────────────────────────┤
│ 应用服务：意图路由 + 权限过滤 + 问答编排      │
├────────────────────────────────────────────┤
│ 检索层：混合检索（BM25+向量）+ bge 重排      │
│          + 知识图谱（设备/产品关联）          │
├────────────────────────────────────────────┤
│ 模型层：私有化 Qwen2.5-14B（vLLM 部署）      │
│          + 领域 LoRA（术语微调）              │
├────────────────────────────────────────────┤
│ 数据层：Milvus 向量库 + PostgreSQL + 文件存储 │
└────────────────────────────────────────────┘
```

### 9.2.3 权限与安全设计

| 需求 | 实现 |
|------|------|
| 数据分级 | 公开 / 部门 / 密级，元数据标记 |
| 权限过滤 | 检索前按用户角色过滤 Collection 分区 |
| 防泄露 | 敏感字段脱敏、问答内容审计 |
| 防注入 | 文档内容消毒、输出安全校验 |

### 9.2.4 运营闭环

```
文档上架 → 自动解析入库 → 定期评估（Ragas）
→ 坏案例回流 → 知识库优化 / 模型微调迭代
→ 月度质量报告（检索命中率、满意度、成本）
```

### 9.2.5 效果指标

| 指标 | 基线 | 目标 |
|------|------|------|
| 检索命中率 | 60% | 85%+ |
| 回答忠实度 | - | 0.85+ |
| 平均响应时间 | - | < 3s |
| 客服/文档支持成本 | 基准 | 下降 40% |

## 9.3 案例方法论总结

### 9.3.1 三个案例的共性框架

```
① 业务价值验证（选高频、痛点明确的场景）
② 技术组合定制（RAG/微调/Agent/图谱按需组合）
③ 数据工程先行（数据质量决定效果上限）
④ 安全合规兜底（权限、审计、人工审核边界）
⑤ 评估闭环迭代（指标 → 定位 → 优化）
⑥ 渐进式上线（POC → 灰度 → 全量）
```

### 9.3.2 技术选型对照表（按行业）

| 场景特征 | 推荐组合 |
|----------|----------|
| 知识密集、更新快（问答） | RAG + 混合检索 + 重排 |
| 专业格式、术语固定（病历/合同） | 微调 + 结构化输出 |
| 关系复杂、多跳推理 | 知识图谱 + GraphRAG |
| 自动化执行（审批/客服） | Agent + Human-in-loop |
| 数据敏感、高合规 | 私有化部署 + 权限审计 |

## 常见问题（FAQ）

**Q1：医疗/金融这种高敏行业，AI 到底敢不敢用？**
A：敢用但要"框住"——AI 只做辅助草稿，关键决策人工负责；权限、审计、脱敏全量做；效果必须用业务指标而非技术指标衡量。

**Q2：企业知识问答落地最难的环节是什么？**
A：不是技术，而是**文档治理**——旧文档格式混乱、内容过期、权责不清。建议先做"文档资产盘点与清洗"，再谈 RAG。

**Q3：怎么向老板证明项目价值？**
A：用业务语言讲三个数：省了多少人时（效率）、提升了多少准确率（质量）、降了多少成本（ROI），并给出上线前后的对比基线。
