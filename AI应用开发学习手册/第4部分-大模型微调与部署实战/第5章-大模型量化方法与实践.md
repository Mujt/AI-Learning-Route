## 5.1 量化原理

### 5.1.1 什么是量化

**量化（Quantization）**：将模型权重/激活从高精度浮点（FP16/BF16，2 字节）映射到低精度（INT8 1 字节 / INT4 0.5 字节），以**减少显存占用、降低推理延迟、减少带宽需求**。

```
FP16: 0.123456789...（2 字节）  →  INT8: 0.123（1 字节）
```

### 5.1.2 量化收益

| 精度 | 每参数占用 | 7B 模型权重 | 速度提升 |
|------|-----------|-------------|----------|
| FP16/BF16 | 2B | 14GB | 基准 |
| INT8 | 1B | 7GB | ~1.5-2× |
| INT4 | 0.5B | 3.5GB | ~2-3× |

> 7B 模型 INT4 量化后，普通 8G 显存显卡即可本地运行。

### 5.1.3 量化为什么能工作

- 神经网络权重**分布集中**（多数在零附近、小范围波动），可用更少位数近似。
- 量化误差在深度网络中**部分互相抵消**，不必然累积放大。

### 5.1.4 量化精度选择

- **FP32/FP16/BF16**：训练/微调用（高精度）。
- **FP8**：新一代推理精度（Hopper/Ada 起硬件支持），损失极小。
- **INT8**：稳健、通用，多数模型损失 <1%。
- **INT4**：显存极限压缩，7B 以上模型损失 1-5%。

## 5.2 量化方法分类

### 5.2.1 按量化时机

| 类型 | 说明 | 代表 |
|------|------|------|
| **PTQ（训练后量化）** | 训练完成后量化权重，无需训练 | GPTQ、AWQ、SmoothQuant |
| **QAT（量化感知训练）** | 训练中模拟量化误差，精度更优 | 需训练数据与算力 |
| **动态量化** | 推理时按层计算缩放（激活量化） | PyTorch 内置 |

### 5.2.2 按量化范围

| 类型 | 说明 |
|------|------|
| 权重量化（Weight-only） | 只量化权重，激活保持高精度（主流 LLM 方案） |
| 权重+激活量化 | 全量化（W8A8），需支持 INT8 矩阵乘的硬件 |
| 混合精度 | 关键层高精度 + 非关键层低精度 |

## 5.3 主流 PTQ 方法详解

### 5.3.1 GPTQ（Post-Training Quantization for GPT）

- **原理**：基于**逐层误差补偿**的优化量化。量化某一层权重时，用误差补偿更新后续权重，最小化输出误差（类似 OBD 剪枝思想，基于 Hessian 矩阵的二阶信息）。
- **特点**：INT4 精度业界标杆、无需训练数据即可离线量化（但使用校准数据效果更好）。
- **适用**：GPU 推理，效果优于朴素 Round-to-Nearest。

```python
# 使用 AutoGPTQ 量化
from transformers import AutoModelForCausalLM
from auto_gptq import AutoGPTQForCausalLM, BaseQuantizeConfig

quantize_config = BaseQuantizeConfig(
    bits=4,                     # 量化位数
    group_size=128,             # 分组量化粒度
    desc_act=True,              # 按激活值降序排列通道
)
model = AutoGPTQForCausalLM.from_pretrained(model_id, quantize_config)
# 用校准数据量化（calibration 100-1000 条样本）
model.quantize(calibration_data)
model.save_quantized("./qwen2.5-7b-gptq-int4")
```

### 5.3.2 AWQ（Activation-aware Weight Quantization）

- **核心洞察**：**权重并非同等重要**——对应激活值大的通道更关键（保护"重要通道"）。
- **原理**：按激活分布统计识别重要通道，对重要权重**乘以缩放因子**再量化，降低重要通道的量化误差（无需训练，速度快于 GPTQ）。
- **特点**：量化速度快、效果与 GPTQ 相当或略优，特别适合大规模模型。

```bash
# 使用 AutoAWQ 量化（支持命令行）
python -m awq.entry --model_path Qwen/Qwen2.5-7B \
  --quant_path ./qwen2.5-7b-awq-int4 \
  --bits 4 --group_size 128
```

### 5.3.3 SmoothQuant

- **问题**：量化**激活**（而非仅权重）时，激活的**离群值**会破坏量化精度。
- **原理**：通过数学变换把激活中的离群值**迁移到权重**中，使激活分布平滑可量化（W8A8 方案）。
- **特点**：实现"权重+激活全 INT8"推理，吞吐高，适合数据中心加速卡。

### 5.3.4 方法对比

| 方法 | 量化对象 | 精度表现 | 速度 | 硬件要求 |
|------|----------|----------|------|----------|
| GPTQ | 权重 INT4/INT8 | 优（逐层补偿） | 中（离线较慢） | GPU |
| AWQ | 权重 INT4 | 优（重要通道保护） | 快 | GPU |
| SmoothQuant | 权重+激活 INT8 | 优（激活平滑） | 快 | 支持 INT8 加速 |
| llama.cpp GGUF | 权重（多种位数） | 良 | 快 | CPU/GPU 皆可 |

## 5.4 GGUF 与 llama.cpp 量化

**GGUF** 是 llama.cpp 生态的模型格式，支持 2/3/4/5/6/8-bit 多种量化级别：

| 量化等级 | 7B 模型大小 | 质量损失 |
|----------|-------------|----------|
| Q2_K | ~2.5GB | 明显 |
| Q4_K_M | ~4.4GB | 轻微（性价比最高） |
| Q5_K_M | ~5.1GB | 很小 |
| Q8_0 | ~7.2GB | 极小 |

```bash
# 下载 GGUF 模型或用转换工具自己量化
# 转换 HF 模型为 GGUF
python convert_hf_to_gguf.py Qwen/Qwen2.5-7B --outfile qwen2.5-7b.gguf
# 再执行量化
./llama-quantize qwen2.5-7b.gguf qwen2.5-7b-q4_k_m.gguf Q4_K_M
```

## 5.5 量化实战：完整流程

### 5.5.1 量化选型决策

```
目标设备：
  GPU 且追求效果 → GPTQ / AWQ（INT4）
  异构/边缘/CPU → GGUF（Q4_K_M）
  需要全 INT8 高吞吐 → SmoothQuant / FP8
先小批量验证精度损失，再全量量化
```

### 5.5.2 量化评估清单

1. **效果验证**：量化前后在评测集跑分，确认损失可接受（<2-3%）。
2. **显存验证**：实测峰值显存（含 KV Cache）。
3. **速度验证**：QPS、TTFT（首 Token 延迟）、TPOT（每 Token 延迟）。
4. **兼容性**：验证量化模型与推理框架（vLLM/llama.cpp）兼容。
5. **端到端回归**：业务场景全流程测试。

### 5.5.3 常见坑

- **校准数据**：GPTQ/AWQ 用 100-500 条与业务分布相似的校准数据，精度更好。
- **group_size**：128 是效果/体积平衡点；64 精度更高但体积略大。
- **INT4 + 长上下文**：KV Cache 显存占比上升，需预留显存或 KV 量化。
- **量化后幻觉**：个别场景量化会放大幻觉，务必做安全回归测试。

## 常见问题（FAQ）

**Q1：量化会不会让模型"变傻"？**
A：大模型（7B+）INT4 量化损失通常 <2-3%，大部分业务可接受；小模型损失更明显。务必用评估集验证而非感觉。

**Q2：GPTQ、AWQ、GGUF 到底用哪个？**
A：GPU 服务 → GPTQ（效果稳）或 AWQ（速度快）；跨设备/CPU/移动端 → GGUF；追求吞吐 → SmoothQuant/FP8。先用 Q4 起步验证。

**Q3：量化后还能微调吗？**
A：可以。QLoRA 就是"量化基座 + LoRA 微调"；也可先量化部署，LoRA 适配器动态加载（不合并权重）。但注意量化基座微调效果略低于 FP16 基座。
