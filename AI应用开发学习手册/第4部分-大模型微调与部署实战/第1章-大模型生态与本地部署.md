## 1.1 大模型开源生态

### 1.1.1 Hugging Face（HF）

全球最大的开源 AI 社区，核心资产：

| 板块 | 内容 |
|------|------|
| Models | 数百万模型（LLM、Embedding、多模态） |
| Datasets | 大规模公开数据集 |
| Spaces | 在线 Demo 应用 |
| Transformers | 最流行的模型加载/训练库 |

**核心用法**：

```python
from transformers import AutoModelForCausalLM, AutoTokenizer
import torch

model_name = "Qwen/Qwen2.5-7B-Instruct"
tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForCausalLM.from_pretrained(
    model_name, torch_dtype=torch.bfloat16, device_map="auto")
```

### 1.1.2 ModelScope（魔搭）

阿里主导的国内开源 AI 平台，对国内用户更友好：**下载速度快、中文模型全、无需科学上网**。

```python
# 使用 modelscope 快速下载/加载
from modelscope import AutoModelForCausalLM, AutoTokenizer
model_name = "Qwen/Qwen2.5-7B-Instruct"
model = AutoModelForCausalLM.from_pretrained(model_name, trust_remote_code=True)
```

**选型建议**：国内网络环境优先 ModelScope；需要最新模型或参与国际生态用 HF（可配镜像 `HF_ENDPOINT=https://hf-mirror.com`）。

## 1.2 本地部署工具对比

| 工具 | 定位 | 优点 | 局限 |
|------|------|------|------|
| **Ollama** | 一键本地跑模型 | 极简单（一条命令）、自动量化、API 兼容 OpenAI | 生产级调优弱 |
| **llama.cpp** | C++ 推理引擎 | 极省内存、支持 CPU/GGUF 量化、边缘友好 | 需手写配置 |
| **vLLM** | 生产级推理服务 | 高吞吐（PagedAttention）、兼容 OpenAI API | 需 GPU |
| **Transformers** | 训练/实验框架 | 最通用、与训练生态一致 | 推理效率一般 |
| **SGLang / TGI** | 高性能服务框架 | 吞吐高、功能全 | 上手门槛高 |
| **LM Studio** | 桌面 GUI | 图形界面、可视化调试 | 面向个人 |

### 1.2.1 Ollama 快速上手

```bash
# 安装后一条命令运行模型
ollama run qwen2.5:7b          # 首次自动下载并运行
ollama run llama3.1:8b

# OpenAI 兼容 API（默认端口 11434）
curl http://localhost:11434/v1/chat/completions \
  -d '{"model":"qwen2.5:7b","messages":[{"role":"user","content":"你好"}]}'

# 管理命令
ollama list / ollama pull qwen2.5:14b / ollama rm qwen2.5:7b
```

### 1.2.2 llama.cpp（GGUF 量化推理）

```bash
# 下载 GGUF 格式模型（HuggingFace 上搜索 -GGUF 后缀）
# 推理（CPU 也能跑小模型）
./main -m qwen2.5-7b-instruct-q4_K_M.gguf -p "你好" -n 256

# 开启 OpenAI 兼容服务
./server -m qwen2.5-7b-instruct-q4_K_M.gguf --port 8080
```

## 1.3 硬件要求与选型

### 1.3.1 显存估算公式

```
模型所需显存 ≈ 参数量 × 每参数字节数
FP16/BF16: 每参数 2 字节      FP32: 4 字节      INT8: 1 字节
7B 模型 FP16 ≈ 14GB（不含 KV Cache 与推理开销，实际约 16-20GB）
```

| 模型规模 | FP16 推理显存 | 建议显卡 |
|----------|--------------|----------|
| 1.5B | ~4GB | RTX 4060 8G |
| 7B | ~16GB | RTX 3090/4090 24G |
| 14B | ~30GB | A100 40G / 双卡 24G |
| 32B | ~64GB | 2×A100 40G |
| 72B | ~144GB | 4×A100 80G 或量化 |

### 1.3.2 本地部署选型决策

```
想快速体验？ ──► Ollama（首选）
CPU/内存为主？ ──► llama.cpp（GGUF Q4）
生产高吞吐？ ──► vLLM（GPU）
边缘设备？ ──► llama.cpp 量化小模型（1-3B）
```

## 1.4 私有化部署实战（DeepSeek/Qwen 本地部署）

### 1.4.1 Ollama + Docker 企业部署方案

```yaml
# docker-compose.yml
version: "3"
services:
  ollama:
    image: ollama/ollama:latest
    container_name: ollama
    ports: ["11434:11434"]
    volumes: ["ollama_data:/root/.ollama"]
    restart: always
    # GPU 支持需配置: devices: - /dev/nvidia0:/dev/nvidia0 ...
```

```bash
docker compose up -d
docker exec ollama ollama pull qwen2.5:14b
# 应用通过 http://内网IP:11434 调用
```

### 1.4.2 部署后的应用接入

```python
from openai import OpenAI
client = OpenAI(base_url="http://localhost:11434/v1", api_key="ollama")
resp = client.chat.completions.create(
    model="qwen2.5:14b",
    messages=[{"role": "user", "content": "介绍一下你们公司的产品"}],
)
print(resp.choices[0].message.content)
```

### 1.4.3 企业本地部署 Checklist

1. **模型选型**：能力 + 显存 + 许可证（商业授权检查）。
2. **量化**：Q4 量化可在损失少量效果下省 70% 显存。
3. **鉴权**：API 网关加 Key 认证与限流。
4. **监控**：GPU 利用率、显存、QPS、延迟。
5. **灾备**：模型文件备份、服务多实例。
6. **升级**：模型版本管理与灰度切换。

## 常见问题（FAQ）

**Q1：本地部署 vs API 调用怎么选？**
A：API 适合快速开发、无 GPU 团队；本地部署适合数据敏感、长期高调用量、网络受限场景。混合架构（本地主力 + API 兜底）最常见。

**Q2：CPU 能跑大模型吗？**
A：能，但很慢。llama.cpp 用 Q4 量化后，7B 模型 CPU 推理约 5-15 token/s（够开发调试，不够生产）。生产推荐 GPU。

**Q3：量化后的模型效果差很多吗？**
A：Q4 量化对 7B+ 模型影响通常在 2-5% 以内（质量损失可接受）；但对小模型（<3B）影响明显，需实测评估。
