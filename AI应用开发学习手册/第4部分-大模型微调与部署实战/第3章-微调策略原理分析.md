## 3.1 大模型微调概述

### 3.1.1 什么是微调

**微调（Fine-tuning）**：在预训练基座模型基础上，用**特定任务数据**继续训练，使模型适配目标领域/任务/风格。

```
预训练模型（通用）--[领域数据微调]--> 领域模型（医疗/法律/代码）
```

### 3.1.2 微调的三大目标

| 目标 | 说明 | 示例 |
|------|------|------|
| 领域知识注入 | 学习垂直领域事实与术语 | 医疗诊断指南 |
| 能力增强 | 提升特定任务能力 | 代码生成、数学推理 |
| 风格与格式对齐 | 学习特定输出风格 | 客服语气、报告格式 |

### 3.1.3 微调 vs RAG vs Prompt（何时用微调）

| 方法 | 解决 | 成本 | 适用 |
|------|------|------|------|
| Prompt 工程 | 调用时的引导 | 最低 | 通用任务微调 |
| RAG | 知识的实时获取 | 中 | 事实问答、私有知识 |
| **微调** | 领域语言与行为固化 | 高 | 特定风格/能力/术语 |

> 决策：**RAG 解决"知道什么"，微调解决"怎么说话"**。领域术语密集、输出格式严格、需要私有能力时微调；知识密集且更新快时 RAG。

## 3.2 传统微调方法

### 3.2.1 全量微调（Full Fine-tuning）

- **做法**：更新模型**所有参数**（如 7B 模型约 70 亿参数）。
- **显存需求**：FP16 训练 7B 模型需约 56-80GB 显存（参数 + 梯度 + 优化器状态）。
- **优点**：效果上限最高，可彻底改变模型行为。
- **缺点**：显存/算力开销巨大、易灾难性遗忘、全模型拷贝存储成本高。

### 3.2.2 传统微调常见问题

1. **灾难性遗忘**：学新任务忘了旧能力。
2. **过拟合**：数据少时在新任务上过拟合。
3. **成本**：每任务一份完整模型副本。

## 3.3 参数高效微调（PEFT）

### 3.3.1 PEFT 思想

**PEFT（Parameter-Efficient Fine-tuning）**：只更新**少量额外参数**（<1%-2%），冻结基座模型，在保持效果的同时大幅降低显存与存储成本。

### 3.3.2 三大流派

| 流派 | 代表方法 | 原理 | 特点 |
|------|----------|------|------|
| **增量式** | Adapter | 在 Transformer 层中插入小模块训练 | 需修改结构，推理有额外开销 |
| **重参数化** | LoRA、Prefix-Tuning | 用低秩矩阵近似权重更新 | 不增加推理延迟，最主流 |
| **选择式** | BitFit | 只训练偏置项 | 极简，效果有限 |

### 3.3.3 各方法详解

**① Adapter Tuning**
在每层 FFN 后插入两层的"瓶颈"结构（先降维再升维），只训练 Adapter 参数。

**② Prefix-Tuning**
在输入序列前添加可学习的**前缀向量**（虚拟 Token），只训练这些前缀。无需改结构，但会占用输入序列长度。

**③ Prompt-Tuning**
类似 Prefix-Tuning，但只加 soft prompt（提示向量），每个任务学习一组向量。

**④ P-Tuning v2**
把 Prefix-Tuning 应用到所有层（深层+浅层），效果更接近全量微调。

**⑤ BitFit**
只训练 bias 项，参数量最小（约 0.1%），效果有限但非常适合资源极端受限场景。

## 3.4 LoRA 与 QLoRA 原理

### 3.4.1 LoRA（Low-Rank Adaptation）核心思想

**核心洞察**：大模型微调时的权重更新矩阵 ΔW 具有**低秩性**——可以用两个小矩阵的乘积近似。

```
原理解读：
  原始权重 W（d×d），更新量 ΔW（d×d）
  LoRA 将 ΔW 分解为：ΔW = B·A，其中
    A（r×d）: 降维矩阵（随机初始化高斯分布）
    B（d×r）: 升维矩阵（初始化为 0）
  r（秩）远小于 d（如 7B 模型 d=4096，r=8/16/64）
  
训练时冻结 W，只训练 A、B → 训练参数量减少 100-10000 倍
推理时合并：W' = W + BA（无额外延迟）或保持 LoRA 分支（灵活切换）
```

### 3.4.2 LoRA 关键配置

| 参数 | 含义 | 常用值 |
|------|------|--------|
| `r`（秩） | 低秩维度 | 8/16/32/64 |
| `alpha`（缩放） | LoRA 缩放系数（alpha/r 决定影响强度） | 16/32 |
| `target_modules` | 作用于哪些层（q_proj/v_proj/k_proj/o_proj/gate_proj 等） | 全 attention + MLP |
| `dropout` | 防过拟合 | 0.05-0.1 |

**经验规则**：`alpha/r` 通常取 2 左右；大模型（70B+）小 r（8-16）；小模型（7B）可 r=32-64。

### 3.4.3 QLoRA（量化 + LoRA）

**QLoRA = 4-bit 量化基座 + LoRA 微调**，在单张 24G 显卡上可微调 65B 模型：

```
1. 基座模型 4-bit NF4 量化（冻结）
2. 加入 LoRA 低秩适配器（训练）
3. 关键技巧：分页优化器（paged optimizer）+ 双重量化（Double Quantization）
4. 推理时反量化合并
```

**QLoRA 显存对比（7B 模型微调）**：

| 方法 | 显存需求 | 效果（相对全量） |
|------|----------|------------------|
| 全量微调 | ~56GB+ | 100%（基准） |
| LoRA（FP16） | ~20GB | ~95-100% |
| QLoRA（4-bit） | ~10GB | ~93-97% |

### 3.4.4 其他高效方法

- **DoRA**：把权重分解为幅度和方向分别学习，效果优于 LoRA。
- **IA3**：只学习对激活的缩放向量，参数更少。
- **Unsloth**：底层优化（Flash Attention + 自定义内核），训练提速 2-3 倍、省显存 70%。

## 3.5 微调效果对比与选型

### 3.5.1 方法选型决策

```
显卡 ≤16GB → QLoRA（4-bit）
显卡 24GB → LoRA 或 QLoRA（7B-14B）
显卡 40GB+ → LoRA（14B-32B）/ 全量微调（≤13B）
追求极致效果 + 资源充足 → 全量微调
```

### 3.5.2 微调工具对比

| 工具 | 特点 | 适合 |
|------|------|------|
| **LLaMA-Factory** | 中文友好、UI/CLI、多方法多模型 | 首选（国人开发） |
| **Unsloth** | 极快、省显存 | 追求速度与性价比 |

### 3.5.3 微调实战配置示例（LLaMA-Factory）

```yaml
# LLaMA-Factory lora.yaml
model_name_or_path: Qwen/Qwen2.5-7B-Instruct
stage: sft
finetuning_type: lora            # lora / full / qlora
lora_rank: 32
lora_alpha: 64
target_modules: all             # 全部线性层
dataset: my_medical_data        # 数据集配置
template: qwen                  # 模板
cutoff_len: 2048
learning_rate: 2.0e-4
num_train_epochs: 3
per_device_train_batch_size: 4
gradient_accumulation_steps: 8
quantization_bit: 4             # 设 4 即 QLoRA
```

**训练超参经验**：
- 学习率：LoRA 一般 1e-4 ~ 5e-4；全量 1e-5 ~ 5e-5。
- epoch：领域数据 2-5 轮；通用数据 1-3 轮（多了易过拟合）。
- warmup：前 3% 步数线性预热。
- 序列长度：与任务匹配（代码/长文档可 4096+）。

## 常见问题（FAQ）

**Q1：LoRA 微调和全量微调效果差多少？**
A：在数据充足场景差异很小（<5%）；LoRA 还可组合多个适配器切换任务。资源有限时 LoRA/QLoRA 是绝对主流。

**Q2：微调需要多少显存？**
A：7B 模型：QLoRA 约 8-12G，LoRA 约 16-24G，全量约 56G+。1.5B 模型 QLoRA 仅需 6G 左右。

**Q3：微调后模型变笨了/变复读了？**
A：常见原因：①学习率过高或 epoch 过多导致过拟合；②数据分布单一；③未混入通用数据（灾难性遗忘）。回归检查数据与超参。
