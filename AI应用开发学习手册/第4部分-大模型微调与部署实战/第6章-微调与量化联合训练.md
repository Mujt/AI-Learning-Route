## 6.1 联合训练概念与流程

### 6.1.1 为什么需要"微调 + 量化"联合

生产落地最常用的组合是**微调适配 + 量化压缩**。但两者有先后顺序与效果耦合问题：

```
方案 A（串联）：微调（FP16）→ 量化（PTQ）
  ✅ 流程简单，但量化误差叠加在微调成果上，可能损失微调收益
方案 B（联合）：量化感知的微调（QAT / QLoRA + 量化）
  ✅ 训练中模拟量化误差，模型"学会"在低精度下工作，精度损失最小
```

### 6.1.2 完整落地流程

```
业务数据 → ① LoRA/QLoRA 微调（FP16 或 4bit 基座）
        → ② 评估微调效果（领域测试集）
        → ③ 量化（PTQ：GPTQ/AWQ 或 QAT 训练）
        → ④ 量化后回归评估（领域 + 通用 + 安全）
        → ⑤ 部署到推理服务（vLLM/llama.cpp）
        → ⑥ 线上监控（效果 + 延迟 + 成本）
```

**关键决策点**：微调用什么精度基座？量化用什么方法？先验证 ③ 的精度损失再决定是否升级 QAT。

## 6.2 QAT（量化感知训练）

### 6.2.1 QAT 原理

**QAT（Quantization-Aware Training）**：在**训练/微调过程中加入"伪量化"操作**（前向时模拟量化取整，反向时用直通估计器 STE 传梯度），让模型参数逐步适应低精度表示：

```
前向：W_q = clamp(round(W / s) , -127, 127) × s   （模拟 INT8 量化）
反向：∂L/∂W ≈ ∂L/∂W_q（STE：取整操作的梯度近似为1）
训练后：模型权重天然适配量化，直接转 INT8/INT4 损失极小
```

### 6.2.2 QAT vs PTQ

| 维度 | PTQ（GPTQ/AWQ） | QAT |
|------|-----------------|-----|
| 训练成本 | 无需训练（小时级） | 需要训练（天级） |
| 精度 | 好（大模型足够） | 更好（小模型差异大） |
| 适用 | 大模型、快速交付 | 小模型、精度敏感场景 |
| 实现复杂度 | 低 | 中高 |

> 实践结论：**7B 以上模型 PTQ 通常够用；3B 以下或精度敏感场景才需 QAT**。

### 6.2.3 QAT 实践（PyTorch / Intel Neural Compressor）

## 6.3 知识蒸馏技术

### 6.3.1 蒸馏原理

**知识蒸馏（Knowledge Distillation）**：用一个**强教师模型（Teacher）**指导**弱学生模型（Student）**学习，把小模型训练到接近大模型的能力：

```
Teacher（如 Qwen2.5-72B）──输出 soft label──▶ Student（如 7B）
Student 损失 = 硬标签损失 + α × 蒸馏损失（soft label 分布匹配）
```

### 6.3.2 蒸馏的三类知识

| 类型 | 内容 | 方法 |
|------|------|------|
| 输出知识 | 教师输出分布 | 软标签（温度缩放） |
| 特征知识 | 中间层表征 | 特征匹配损失 |
| 关系知识 | 样本间关系 | 关系蒸馏 |

### 6.3.3 蒸馏 + 量化的协同

- **路径 1**：先蒸馏（大→小）再量化（小→更小）：大模型 → 7B 学生 → INT4 部署。
- **路径 2**：量化小模型 + 大模型在线指导（logit 蒸馏，提升量化模型精度）。

**典型应用**：DeepSeek-R1 用 671B 教师蒸馏出 1.5B-70B 系列模型，小模型获得推理能力。

## 6.4 微调 + 量化联合实践

### 6.4.1 QLoRA：微调即量化（最流行的联合方案）

QLoRA 本身就是"量化 + 微调"的联合——**基座 4-bit 量化 + LoRA 训练**，且训练产物（LoRA 适配器）可直接叠加在量化模型上：

```
流程：4bit NF4 量化基座（冻结） → LoRA 低秩适配器训练
部署：量化基座 + 合并/加载 LoRA → 直接 INT4 推理
优点：①单卡微调大模型 ②训练与部署精度一致 ③无二次量化损失
```

```python
# LLaMA-Factory 中开启 QLoRA（4bit 基座 + LoRA）
quantization_bit: 4
quantization_type: nf4            # nf4 / fp4
double_quantization: true
finetuning_type: lora
```

### 6.4.2 微调后 PTQ 的优化技巧

- **先微调再量化**时，校准数据用**微调后的业务数据**（而非通用数据）。
- 微调 LoRA 合并后量化（合并权重） vs 不合并（LoRA + 量化基座），实测选优。
- 对量化放大敏感的任务（数学、代码）用 QAT 兜底。

### 6.4.3 联合实验设计（对比实验）

| 实验组 | 方案 | 领域分数 | 显存 | 说明 |
|--------|------|----------|------|------|
| A | FP16 微调（基线） | 78.2 | 16G+ | 效果基准 |
| B | QLoRA 微调（4bit） | 77.5 | 9G | 微调成本大降 |
| C | 微调 + PTQ(GPTQ-INT4) | 76.1 | 4G | 部署最省 |
| D | 微调 + QAT(INT4) | 77.0 | 需训练 | 精度最优的量化 |

**选择建议**：资源充足 → A/C 组合；资源有限 → B/D；一般业务 → B + C 性价比最高。

## 6.5 联合训练效果验证

- **精度指标**：领域测试集 + 通用回归集 + 安全集。
- **资源指标**：显存、推理速度（QPS/TTFT）、体积。
- **业务指标**：线上 A/B（用户满意度、任务成功率）。
- **验证矩阵**：每个方案都记录"精度 + 资源"两个维度，做权衡决策。

## 常见问题（FAQ）

**Q1：QLoRA 训练出来的模型还需要再量化吗？**
A：不需要，QLoRA 基座本身就是 4bit 量化，训练产物直接低精度部署；这是它最大的工程优势。

**Q2：什么时候必须用 QAT 而不是 PTQ？**
A：①小模型（≤3B）量化后掉点明显；②精度极其敏感（医疗/金融决策）；③硬件要求 W8A8 全量化。其他情况 PTQ 性价比更高。

**Q3：蒸馏出的模型真的能追平大模型吗？**
A：能接近但不能完全追平（尤其是复杂推理）。蒸馏适合"把能力打包进小模型"的部署场景，追求极致效果仍用大模型。
