# 第 1 章 可视化低代码 Agent 框架

- 理解低代码 Agent 平台的价值与适用场景

## 1.1 为什么需要低代码 Agent 框架

Agent 开发涉及模型调用、工具接入、记忆管理、流程编排、发布运维等复杂环节。低代码平台将其**可视化、组件化**，带来三大价值：

1. **降低门槛**：产品、运营人员无需写代码即可构建 AI 应用。
2. **加速迭代**：拖拽编排比改代码快一个数量级。
3. **内置能力**：多模型接入、插件市场、知识库、发布渠道开箱即用。

**适用判断**：需求标准化、追求速度 → 低代码平台；深度定制、独特算法、需要完全掌控 → 代码开发（LangChain/LangGraph）。

## 1.2 Coze（扣子）平台

### 1.2.1 平台简介

Coze 是字节跳动推出的 AI Bot 开发平台，国内版（coze.cn）与海外版（coze.com）生态不同。核心理念：**"每个人都能创建自己的 AI Bot"**。

### 1.2.2 五大核心模块

| 模块 | 能力 | 关键点 |
|------|------|--------|
| **Bot（智能体）** | 对话式智能体的编排入口 | 人设与回复逻辑（提示词） |
| **工作流** | 可视化流程编排 | 节点：大模型/代码/知识库/条件/循环 |
| **插件（Tools）** | 扩展工具能力 | 内置 200+ 插件 + 自定义 API 插件 |
| **知识库** | 上传文档供检索 | 分段策略、召回设置 |
| **数据库/变量** | 状态存储与记忆 | 记忆变量、KV 存储 |
| **发布渠道** | 多端分发 | 抖音、飞书、微信、Web SDK、API |

### 1.2.3 构建一个 Bot 的标准流程

```
① 新建 Bot → ② 编写人设与回复逻辑（Prompt）
③ 添加能力：工作流 / 插件 / 知识库
④ 配置触发器与开场白 → ⑤ 测试调试 → ⑥ 发布到渠道
```

**实战示例：小红书文案助手 Bot**
- 人设：资深小红书运营，熟悉种草文案套路。
- 工作流：接收主题 → 调用"热点搜索"插件 → 大模型生成 3 版文案 → 格式美化。
- 插件：热点搜索、图片生成（生成封面图）。
- 发布：发布到微信小程序 + Web。

### 1.2.4 Coze 优势与注意点

- 优势：上手极快、插件生态丰富、多端分发无缝、扣子空间（个人 Agent 空间）成熟。
- 注意：国内版数据与模型受平台约束；深度定制能力有限；复杂业务逻辑仍需工作流内的"代码节点"。

## 1.3 Dify 平台（Agent 视角）

Dify 在 RAG 部分已介绍，本节聚焦其 Agent 能力：

### 1.3.1 Agent 编排方式

| 方式 | 说明 | 适用 |
|------|------|------|
| Agent（Function Calling） | LLM 自主选工具、多轮调用 | 需要自主决策 |
| 工作流 Agent 节点 | 在流程中嵌入 Agent 子任务 | 流程中某步需要自主性 |
| 多 Agent 协作（实验） | 多个 Agent 节点分工协作 | 复杂任务拆解 |

### 1.3.2 Dify Agent 实战配置要点

1. **工具编排**：内置工具 + 自定义 OpenAPI 工具 + 内置 Agent 策略（ReAct/Function Calling）。
2. **上下文变量**：会话变量、文件变量在工具间传递。
3. **模型配置**：为 Agent 选择带 Function Calling 能力的模型（DeepSeek、GLM-4、Qwen）。
4. **失败回退**：工具调用失败时设置错误分支。

## 1.4 低代码平台对比

| 维度 | Coze | Dify | FastGPT |
|------|------|------|---------|
| 定位 | Bot 分发平台 | LLMOps 应用平台 | 知识库问答平台 |
| 上手难度 | 极易 | 中 | 低 |
| 插件生态 | 极丰富（字节系） | 丰富（自建+市场） | 中 |
| 知识库 | 支持 | 强（多路召回） | 强（QA 拆分） |
| 发布渠道 | 抖音/飞书/微信/API | Web/API/嵌入 | 微信/钉钉/飞书/API |
| 私有化 | 企业版 | 开源可私有化 | 开源可私有化 |
| 深度定制 | 受限 | 可扩展（代码节点） | 可扩展 |

**选型建议**：C 端 Bot 分发选 Coze；企业应用平台选 Dify；知识库问答选 FastGPT。

## 1.5 低代码 + 代码混合架构

成熟团队通常采用**混合架构**：

```
前台（快速验证/轻量场景）→ 低代码平台（Coze/Dify）
中台（核心业务逻辑）     → 代码开发（LangGraph 编排 + API）
模型层（统一网关）       → OneAPI / LiteLLM 统一接入
```

- 低代码平台通过 **API 方式**暴露给代码系统调用（Dify/Coze 均提供完整 API）。
- 复杂能力（专用算法、大文件处理）封装为自定义插件/API 供低代码平台调用。

## 常见问题（FAQ）

**Q1：低代码平台做的应用能承载生产流量吗？**
A：可以。Dify/Coze 均提供 API 与高可用部署；但极端定制、超低延迟场景仍需自研。

**Q2：平台会绑定我的模型和数据吗？**
A：Dify/FastGPT 开源版可完全私有化，模型、向量库、数据库均可自选；Coze 国内版数据存于字节平台，需注意数据合规。

**Q3：低代码会不会被代码方案替代？**
A：两者互补。低代码解决 80% 的标准化需求，代码解决 20% 的复杂定制。掌握"先低代码验证、再代码深化"的能力是 Agent 工程师的核心竞争力。
