## 6.1 项目一：HR 智能体平台

### 6.1.1 项目背景与需求

为大型企业构建一体化 HR 智能体平台，覆盖**员工服务**与**招聘业务**两大场景：

```
员工自助服务（C 端）：
  政策问答（年假/社保/报销）、流程引导、人事档案查询
招聘业务（B 端）：
  JD 生成、简历初筛、面试邀约、面试评价汇总
```

### 6.1.2 技术架构

```
┌────────── 员工入口 ──────────┐
│ 企业微信/钉钉/Web 前端        │
├────────── Agent 层 ──────────┤
│ 主管 Agent（意图识别与路由）    │
│  ├── 政策问答 Agent（RAG）    │
│  ├── 流程引导 Agent（工作流）  │
│  ├── 招聘 Agent（工具调用）    │
│  └── 审批 Agent（Human-in-loop）│
├────────── 服务层 ────────────┤
│ HR 系统 API / OA 系统 / 企业知识库│
└──────────────────────────────┘
```

### 6.1.3 核心设计

**1. 政策问答 Agent（RAG）**
- 知识库：HR 制度文档（分级权限：全员/部门/管理层）。
- 检索：混合检索 + 重排，强制引用政策条款编号。
- 兜底：不确定时转人工（企微客服会话）。

**2. 招聘 Agent（工具调用链）**
```
输入简历 → 解析（OCR/结构化）→ 匹配 JD 打分 → 生成初筛报告
→ 自动邀约（对接邮件/短信 API）→ 记录面试官评价 → 汇总对比
```

**3. 敏感操作 Human-in-the-loop**
- 修改薪资、删除档案、批量通知等**高权限操作**必须人工审批。
- 用 LangGraph `interrupt()` 实现"Agent 起草 → 主管确认 → 执行"。

### 6.1.4 商业级关键点

| 维度 | 方案 |
|------|------|
| 权限安全 | 用户身份（企微 SSO）→ 检索过滤 + 工具权限 |
| 合规审计 | 全量操作日志 + 敏感词过滤 + 数据脱敏 |
| 准确性 | 政策类问题设置"引用必答"，未命中必须转人工 |
| 监控 | 意图路由成功率、检索命中率、转人工率看板 |

## 6.2 项目二：DeepResearch 智能体

### 6.2.1 项目背景与需求

**DeepResearch** 指"自主深度调研"智能体：给定一个研究主题，自动完成**问题拆解、资料检索、多源交叉验证、报告撰写**。

```
输入："调研 2026 年 RAG 技术发展趋势"
输出：结构化研究报告（现状/趋势/厂商对比/建议）+ 引用来源列表
```

### 6.2.2 核心架构（研究型多 Agent）

```
研究主管（Planner）
  ├── 拆解：现状 / 技术趋势 / 主流厂商 / 挑战与建议
  ├── 检索研究员 × N（并行）：网络搜索 + 论文库 + 行业报告
  ├── 分析员：交叉验证、去伪存真、识别冲突
  ├── 写作者：按大纲生成报告章节
  └── 审稿人：事实核查、引用校验、格式修订
```

### 6.2.3 关键技术点

**1. 检索增强与联网**
- 工具：联网搜索（Tavily/Bing/SerpAPI）+ 学术库（arXiv）+ RAG 知识库。
- 检索策略：每子问题多轮检索，去重去噪，保留来源 URL。

**2. 来源可信度分级**
- 来源分级：官方文档 > 权威媒体 > 技术博客 > 个人分享。
- 交叉验证：同一结论至少 2 个独立来源支持才采信。

**3. 冲突处理**
- 发现来源矛盾 → 记录分歧 → 报告中明确呈现"各方观点"而非强行统一。

**4. 引用与报告结构**

```
# 标题
## 1. 摘要（200字执行摘要）
## 2. 现状分析
## 3. 趋势研判
## 4. 厂商/方案对比（表格）
## 5. 风险与建议
## 参考资料（带链接与访问日期）
```

### 6.2.4 性能与成本控制

- 长任务：任务级进度流式输出（WebSocket/SSE），用户可见"正在调研第 2/5 步"。
- 成本：限定检索轮次、报告长度、Agent 迭代上限；支持"深度/标准/快速"三档。

## 6.3 项目三：电商 Agent Copilot

### 6.3.1 项目背景与需求

为电商运营/客服团队构建 **Copilot（副驾驶）** 模式 Agent——不是替代人，而是**辅助人**，覆盖售前、售中、售后全链路：

```
智能客服（用户侧）：售前咨询、售中催单、售后退款（有边界）
运营助手（员工侧）：商品文案、竞品分析、差评洞察、活动策划
管理看板（决策侧）：销售趋势、库存预警、ROI 分析
```

### 6.3.2 智能客服 Agent 架构

```
用户消息 → 意图识别（购买/物流/售后/投诉）
  ├── 商品咨询 → 商品知识库 RAG + 促销信息
  ├── 物流查询 → 订单 API → 物流 API（工具调用）
  ├── 售后 → 退款政策判断 → 金额权限校验
  │        └── 超权限 → 转人工 + 保留上下文
  └── 投诉 → 安抚话术（情绪识别）→ 升级流程
```

**安全红线设计**：
- 退款金额上限（如 <500 元自动，≥500 转人工）。
- 禁止泄露他人订单/用户隐私。
- 敏感话题检测 → 转人工。

### 6.3.3 运营助手 Agent（员工侧）

| 能力 | 实现 |
|------|------|
| 商品文案生成 | 商品信息 + 卖点提示 → 多版本文案 |
| 竞品分析 | 抓取竞品数据 → 对比表格 + 建议 |
| 差评洞察 | 差评聚类 → 根因分析 → 改进建议 |
| 活动策划 | 目标 + 预算 → 方案（选品/促销/节奏） |

### 6.3.4 Copilot 模式的核心原则

1. **人机分工明确**：Agent 提供"草稿/分析/建议"，最终决策权在人。
2. **可解释**：每条建议附依据（数据来源、推理过程）。
3. **渐进增强**：先做信息检索与生成类（低风险），再做自动化执行（高风险，需审批）。

## 6.4 商业级 Agent 共性方法论

### 6.4.1 通用交付流程

```
① 场景盘点（高频、高耗时、规则相对清晰的场景优先）
② 效果 POC（1-2 周验证准确率与用户接受度）
③ 安全评审（权限、合规、红线操作定义）
④ 灰度上线（10% 流量 → 观察 → 放量）
⑤ 持续评估（效果指标 + 用户反馈 + 成本监控）
```

### 6.4.2 商业级必做清单

| 类别 | 必做项 |
|------|--------|
| 安全 | 权限矩阵、敏感操作审批、Prompt 注入防护、数据脱敏 |
| 可靠 | 工具失败重试、兜底转人工、超时处理、限流 |
| 可观测 | 全链路追踪（LangSmith）、指标看板、告警 |
| 成本 | Token 预算、缓存复用、模型分级（简单用便宜模型） |
| 体验 | 流式输出、进度提示、失败优雅降级 |

## 常见问题（FAQ）

**Q1：Agent 项目失败最常见的原因？**
A：不是技术不行，而是①场景选错（规则模糊/需要人拍板的任务）；②效果没有量化验证；③安全与兜底设计缺失导致不敢上线。先跑 POC 验证 ROI 再投入。

**Q2：Agent 转人工的边界怎么定？**
A：按"风险等级 + 明确度"矩阵：高风险（资金、隐私）+ 低明确度 → 强制转人工；低风险 + 高明确度 → 全自动。

**Q3：如何评估 Agent 项目的业务价值？**
A：核心指标：人工处理时长下降率、服务响应时长、用户满意度、错误率、转人工率。上线前定基线，上线后月度对比。
