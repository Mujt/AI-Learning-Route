## 2.1 大模型应用实例与 Prompt 技巧

大模型的能力通过**输入（Prompt）→ 生成 → 应用**的范式呈现。经典应用实例：

| 应用类型 | 示例 | 关键 Prompt 技巧 |
|----------|------|------------------|
| 文本生成 | 营销文案、新闻稿 | 明确角色 + 输出格式 |
| 代码生成 | 函数实现、Bug 修复 | 给出输入/输出示例 |
| 知识问答 | 企业知识库问答 | 限定来源 + 要求引用 |
| 摘要/翻译 | 长文档摘要、多语言翻译 | 指定长度 + 语言风格 |
| 数据提取 | 从文本抽取结构化字段 | 定义 JSON Schema 示例 |

**为什么理解原理很重要**：只有理解 Token、上下文窗口、注意力机制，才能解释为什么"上下文越长越容易出错"、"为什么模型记不住聊天开头"、"为什么 RAG 能减少幻觉"。

## 2.2 Token：大模型处理文本的基本单元

### 2.2.1 什么是 Token

Token 是模型处理文本的**最小语义单元**，可以是单词、子词或字符。中文通常一个字 ≈ 1-2 个 Token，英文一个单词 ≈ 1 个 Token。

- 分词示例："你好世界" → 可能被切分为 ["你好", "世界"] 或 ["你", "好", "世", "界"]
- **BPE（Byte Pair Encoding）**：主流分词算法，通过词频统计迭代合并高频子词，平衡词汇表大小与语义粒度。

### 2.2.2 为什么 Token 重要

1. **计费单位**：所有 API 按 Token 计费（输入 + 输出）。
2. **上下文窗口**：模型最大输入长度按 Token 计算（如 128K = 约 20 万字）。
3. **性能瓶颈**：生成是逐 Token 进行的，Token 数直接决定响应速度与成本。
4. **长文本处理**：中文 Token 效率高（相对英文），但长上下文仍有注意力计算成本问题。

## 2.3 Transformer 架构

### 2.3.1 为什么需要 Transformer

- 循环神经网络（RNN/LSTM）存在**长距离依赖**问题与**无法并行**的缺陷。
- Transformer 于 2017 年由 Google 提出（论文 *Attention Is All You Need*），用**自注意力机制**取代循环结构，实现全并行计算，一举成为大模型基石。

### 2.3.2 整体结构

```
输入序列 → [Embedding + 位置编码] → 多头自注意力 → 前馈网络（FFN）→ 输出
（可堆叠 N 层，每层带残差连接与 LayerNorm）
```

- **编码器（Encoder）**：双向注意力，理解全句语义（BERT 类模型使用）。
- **解码器（Decoder）**：带掩码的自注意力 + 交叉注意力，逐 Token 生成（GPT 类模型使用）。
- **GPT 系列**：仅用 Decoder，称为"自回归"架构，当前主流 LLM（GPT、Llama、Qwen、DeepSeek）均为该架构。

### 2.3.3 核心组件

| 组件 | 作用 |
|------|------|
| Token Embedding | 将 Token 映射为高维向量 |
| 位置编码（Positional Encoding） | 注入词序信息（Sinusoidal 或 RoPE 旋转位置编码） |
| 多头自注意力（Multi-Head Attention） | 建模词与词之间的关联权重 |
| 前馈网络（FFN） | 逐位非线性变换，扩大模型容量（含 SwiGLU 等激活） |
| 残差连接 + LayerNorm | 稳定深层网络训练（RMSNorm 为轻量变体） |

## 2.4 多头注意力机制

### 2.4.1 自注意力（Self-Attention）

对每个 Token，通过三个可学习矩阵生成 **Q（查询）、K（键）、V（值）**，注意力分数计算：

```
Attention(Q, K, V) = softmax(QK^T / √d_k) · V
```

- `QK^T`：衡量两 Token 的相关性
- `/√d_k`：缩放，防止点积过大导致 softmax 梯度消失
- 结果：每个 Token 的表示是全部 Token 的加权和，权重由相关性决定

### 2.4.2 为什么需要"多头"

单一注意力只能捕获一种相关性模式；**多头注意力**将 Q/K/V 切成 h 份（如 8/16/32 头），各自独立计算注意力，再拼接融合，从而同时捕获语法关系、指代关系、语义相似等多种模式。

### 2.4.3 复杂度与变体

- 标准注意力复杂度 O(n²)（n 为序列长度），是长上下文的瓶颈。
- 高效变体：FlashAttention（IO 优化）、Sparse Attention（稀疏）、KV Cache（推理加速）、GQA/MQA（分组查询注意力，减少 KV 缓存显存）。

## 2.5 预训练 → SFT → RLHF 三阶段训练范式

### 2.5.1 第一阶段：预训练（Pre-training）

- **目标**：从海量无标注文本（数万亿 Token）中学习语言规律。
- **任务**：Next Token Prediction（自回归）或 Masked LM（掩码预测）。
- **产物**：基座模型（Base Model），会"接龙"但不会对话/遵循指令。
- **成本**：数千张 GPU，数月训练（DeepSeek-V3 仅 557 万美元训练成本，靠工程创新）。

### 2.5.2 第二阶段：监督微调（SFT）

- **目标**：教会模型遵循指令、以问答形式交互。
- **数据**：人工标注的高质量指令-回答对（Instruction Data）。
- **方法**：在基座模型上继续训练，交叉熵损失最小化。
- **产物**：指令模型（Instruct/Chat Model），如 GPT-3.5-turbo 相对 GPT-3 的提升主要来自此步。

### 2.5.3 第三阶段：人类反馈强化学习（RLHF）

| 子步骤 | 说明 |
|--------|------|
| 奖励模型训练（RM） | 用人类对多个回答的偏好排序训练打分模型 |
| PPO 强化学习 | 以 RM 为奖励信号，微调 SFT 模型，并加 KL 约束防止跑偏 |
| 对齐目标 | 有用（Helpful）、诚实（Honest）、无害（Harmless） |

- 轻量替代方案：**DPO（Direct Preference Optimization）**——无需奖励模型和强化学习，直接用偏好对优化，更简单稳定。

### 2.5.4 三阶段对比

| 阶段 | 数据 | 计算量 | 作用 |
|------|------|--------|------|
| 预训练 | 海量无标注文本 | 极大 | 语言能力 |
| SFT | 万-百万级指令对 | 中 | 指令遵循 |
| RLHF/DPO | 人类偏好数据 | 小 | 价值观对齐 |

## 2.6 大模型应用中的关键概念补充

- **上下文窗口（Context Window）**：模型一次能"看到"的最大 Token 数，超出部分被截断或遗忘。
- **温度（Temperature）**：采样随机性参数，低温度（0-0.3）确定性高，适合代码/问答；高温度（0.7-1.0）创造性高，适合文案。
- **Top-P / Top-K**：核采样与 top-k 采样，控制候选词范围。
- **KV Cache**：推理时缓存历史 Token 的 K/V 向量，避免重复计算，是加速推理的关键。
- **涌现能力（Emergent Ability）**：参数量超阈值后出现的上下文学习（In-context Learning）、思维链（CoT）、指令遵循等能力。

## 常见问题（FAQ）

**Q1：为什么大模型生成是一字一字往外蹦？**
A：自回归架构要求逐个 Token 生成，每次生成都依赖前面已生成的 Token，这也是推理慢的根本原因。

**Q2：基座模型和对话模型有什么区别？**
A：基座模型只会续写文本；对话模型经过 SFT/RLHF 后学会"用户问→助手答"的交互模式。

**Q3：长文档对话时模型为什么"忘了"开头？**
A：超出上下文窗口的内容会被截断，且注意力对长序列的早期信息权重衰减，需借助 RAG 或长上下文模型解决。
