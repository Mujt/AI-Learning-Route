## 5.1 注意力机制的本质

### 5.1.1 直觉：数据库检索范式

注意力机制本质是**软性检索（Soft Retrieval）**：

```
查询（Query）：你要找什么（如"谁偷吃了蛋糕？"）
键（Key）：    候选条目的标识（如人名标签）
值（Value）：  候选条目的内容（如人说的话）

注意力 = 用 Query 与所有 Key 算相似度 → 归一化成权重 → 加权求和 Value
```

这与数据库查询的区别：**不二选一，而是按相关程度对所有条目加权融合**。

### 5.1.2 注意力的数学形式

```
Attention(Q, K, V) = softmax( QKᵀ / √d_k ) V

步骤拆解：
① QKᵀ：Query 与所有 Key 的点积相似度矩阵（n_q × n_k）
② /√d_k：缩放稳定梯度
③ softmax：行归一化成概率分布（权重和=1）
④ ×V：按权重加权求和，得到每个 Query 的输出
```

### 5.1.3 注意力权重可视化

注意力矩阵（n_q × n_k）每一行是"当前 Token 对所有 Token 的关注程度"：

```
        词1  词2  词3  词4
词1  [0.1  0.7  0.1  0.1]   ← "我"主要关注"爱"
词2  [0.2  0.2  0.5  0.1]
词3  ...
```

可视化工具可显示句子中"指代关系"（"它"→"苹果"）、"语法依赖"等语言学模式。

## 5.2 注意力机制的分类

### 5.2.1 按数据来源

| 类型 | Q/K/V 来源 | 用途 |
|------|-----------|------|
| **Self-Attention（自注意力）** | 全部来自同序列 | 建模序列内部关系（编码器/GPT） |
| **Cross-Attention（交叉注意力）** | Q 来自本序列，K/V 来自另一序列 | 翻译（解码器看源语言）、多模态（文本看图像） |
| **Encoder-Decoder Attention** | 交叉注意力的特例 | Seq2Seq 任务 |

### 5.2.2 按掩码（Mask）

| 掩码类型 | 规则 | 用途 |
|----------|------|------|
| 无掩码（双向） | 看全序列 | BERT、编码器 |
| 因果掩码（Causal） | 只看自己及之前 | GPT、解码器生成 |
| Padding 掩码 | 忽略填充位 | 变长批次 |

**因果掩码实现**：

```python
# 上三角矩阵置 -inf（禁止看未来）
seq_len = 8
causal_mask = torch.tril(torch.ones(seq_len, seq_len)).bool()
scores = scores.masked_fill(~causal_mask, float("-inf"))
```

### 5.2.3 按作用对象

- **局部注意力**：只关注窗口内邻居（窗口注意力）。
- **全局注意力**：少数"锚点 Token"看全序列。
- **稀疏混合**：全局 + 局部结合（Longformer、BigBird）。

## 5.3 多头注意力（Multi-Head Attention）深入

### 5.3.1 为什么多头有效

单头注意力 = 一个线性投影 + 一个 softmax 分布，表达力有限。多头把 Q/K/V 投影到 h 个不同子空间：

```
每个头："我"从不同视角关注其他词——
  头1：语法视角（主谓关系）
  头2：指代视角（代词指向）
  头3：语义视角（同义词关联）
  头4：位置视角（相邻词）
```

实验证实不同头确实学到不同功能（可做注意力头分析），且**存在冗余**（部分头可裁剪而不掉点）。

### 5.3.2 完整计算流程

```
X（n×d_model）
→ 每头独立投影：Q_h = X·W_Qh（d_k 维），K_h，V_h
→ 每头计算 softmax(Q_h K_hᵀ/√d_k)·V_h
→ 拼接所有头输出（h×d_k = d_model）
→ 输出投影 W_O 融合
```

**参数量**：d_model×d_model（Q/K/V 各一个）+ d_model×d_model（O 投影），与单头相同，只是拆分方式不同。

### 5.3.3 多头注意力的代码扩展（含偏置与 GQA）

```python
def attention_scores(Q, K, V, head_mask=None):
    d_k = Q.size(-1)
    scores = torch.matmul(Q, K.transpose(-2, -1)) / (d_k ** 0.5)
    if head_mask is not None:
        scores = scores + head_mask
    return F.softmax(scores, dim=-1) @ V
```

## 5.4 注意力计算复杂度的瓶颈

### 5.4.1 O(n²) 问题

- 自注意力需要计算 n×n 的注意力矩阵。
- 序列 n=1 万时，矩阵有 1 亿个元素——**显存与计算随长度平方增长**。
- 这是长上下文（100K+）推理的核心挑战。

### 5.4.2 现代注意力变体

| 变体 | 思路 | 效果 |
|------|------|------|
| **FlashAttention** | IO 感知：分块计算 + 在线 softmax，避免读写大矩阵 | 提速 2-5×，省显存（不改变数学结果） |
| **GQA（分组查询注意力）** | K/V 头数少于 Q 头数（共享 KV） | 减少 KV Cache 显存 70-90% |
| **MQA（多查询注意力）** | 所有 Q 头共享一组 KV | 更省，精度略降 |
| **稀疏注意力** | 只算部分位置对（窗口/全局锚点） | 线性复杂度，精度略降 |
| **线性注意力** | 用核函数分解避免显式矩阵 | 线性复杂度，效果欠佳 |
| **Sliding Window** | 固定窗口局部注意力 | 长序列低成本 |

### 5.4.3 推理时 KV Cache 的作用

生成时，历史 Token 的 K/V 无需重算——**缓存**起来：

```
每生成一个新 Token：
  只计算新 Token 的 Q、K、V
  新 Token 的 Q 与所有历史 K 算注意力
  输出 → 新 K/V 追加进缓存
```

这是解码加速的关键（但显存成本也来自 KV Cache，详见第 4 部分）。

## 5.5 注意力的其他关键概念

- **注意力得分温度**：除以 √d_k 是默认"温度"，降低可让分布更尖锐。
- **Dropout on Attention**：对注意力权重做 dropout（正则化，常用 0.1）。
- **位置偏置**：ALiBi（线性距离偏置）在注意力分数上加距离惩罚，替代位置编码。
- **注意力头剪枝**：部分头冗余，可裁剪以压缩模型。
- **可解释性**：注意力权重 ≠ 模型解释的全部，但仍是重要的分析窗口。

## 常见问题（FAQ）

**Q1：多头注意力头数怎么选？**
A：常见规则：d_model = 头数 × 头维度，头维度通常取 64 或 128（如 d=4096 → 32 头）。并非越多越好，头间冗余后收益递减。

**Q2：注意力和 RNN 的"注意力"是一回事吗？**
A：同源。传统 RNN seq2seq 用"Bahdanau 注意力"对齐源词；Transformer 的自注意力是其扩展——任意两位置直接计算，不再依赖循环结构。

**Q3：为什么因果掩码用 -inf 而不是 0？**
A：softmax 中 -inf 使对应概率为 0，彻底屏蔽未来信息；用 0 则只会降低权重而不会完全屏蔽。
